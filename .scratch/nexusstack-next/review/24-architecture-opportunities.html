判据（来自 codebase-design，非本报告自创）

删除测试把模块删掉，复杂度是不是在 N 个调用点重新长出来？是 → 它是个真模块。
接口就是测试面测试必须越过与调用方同一道缝。绕过接口才能测 = 缝画错了。
两个适配器一个适配器只是假设的缝，两个才是真的缝。本仓的端口基本都有两个（内存 + EF/磁盘）。

机会一：授权在五个模块里长成了两种形状 杠杆最大

一个关注点，两种机制，五处声明

Identity 挂自己的授权过滤器（算权限键 + 查会话版本）；其余四个模块手写 RequireAuthorization() / AllowAnonymous()。同一件事——"这个端点谁能碰"——在仓库里有两种写法，而它们**必须与边缘的路由表逐条对应**。

模块既有的授权判定：过滤器住在 Identity.Endpoints，另外四处各写一遍框架调用
接口（提议）按分组声明意图：RequirePermission(key) / RequireAuthenticated() / Public()
实现权限键的解析与会话版本检查——调用方看不见
删除测试通过 删掉它，五个模块会各自长回一份判定逻辑
第二消费者已满足 不变量 7 要求 ≥2 个消费者；这里有 5 个
代价新增一个共享程序集（BuildingBlocks.AspNetCore）——而不变量 7 的判据是"被第二个消费者证明需要"，它正好卡在边界上

现状的隐患不在"能不能跑"（它有测试：ContextAuthorizationTests），而在**它只对了一半**：四个模块的判定与边缘路由表的对应关系，靠人读两份文件维持。

机会二：三个 verify 脚本里同一坨"起宿主 + 等就绪 + curl" 最便宜

三段旅程，三份几乎相同的引导代码

verify-user-journey.ps1、verify-write-paths.ps1、verify-cross-service-trace.ps1 各自：起两个进程、轮询 /health/ready、装 curl、收尾清理。它们验的是**不同的旅程**（同一个接口面），复用不了的是实现。

模块scripts/lib/hosts.ps1：Start-Hosts / Wait-Ready / Stop-Hosts
接口就是测试面通过 三个脚本点同样的三个函数；旅程本身留在各自脚本里
删除测试通过 删掉它，第三份引导代码会再抄一遍
杠杆第 4 条旅程正在变便宜；而"只杀自己起的进程"这类修补只写一次
代价几乎为零——但它**不在测试射程内**（这些脚本手动跑），所以改动得靠真跑一遍验
已知教训本轮刚修过：三个脚本此前都 Stop-Process -Name dotnet，会杀掉机器上所有 .NET 进程

机会三：不变量覆盖率表靠字符串指针 低风险

表 → 测试名是字符串，改名靠一条测试兜着

InvariantCoverage.cs 把八条不变量指向具体测试的**名字**；InvariantCoverage_IsCompleteAndPointsAtRealTests 保证指针不悬空。它有效——但"有效"靠的是每次改名都跑那条测试。

接口（提议）[Trait("invariant","3")] + 反射枚举，表由事实生成而不是抄写
删除测试一半 删掉表，八条不变量的可达性就只剩测试名可读
代价反射枚举要走 SourceAssemblyPaths() 那套守卫（空枚举必须响亮失败），否则会复制出本仓最反复吃的那类亏
建议现在够用。不做，除非表里再长出第 9 条不变量

看过的机会（有意不做，附理由）

机会为什么不做什么会改变这个决定
把各模块的 Failure(Error)（6 行 × 5 份）上移 AGENTS.md 把它写成**决定而非遗漏**：那是每个服务自己的 HTTP 契约，统一等于用一个共用函数锁死五个服务的状态码语义 出现第六个模块，且它们的映射表逐字相同
把内存适配器从产品代码里移出去，只留测试替身 它们不是替身：是本仓"无库也能端到端跑起来"的能力（ADR-0005 的落地形态），且每个端口两个适配器正是"缝是真的"的证据 内存适配器开始与 EF 适配器语义漂移（那才是它变成负债的信号）
给 NexusStackDbContextOptionsExtensions 再抽一层"上下文构建器" 它已经是那个深的模块：三个知识（迁移历史表归 schema、瞬时重试、模型缓存键含 schema）藏在两行调用背后。再抽只是加壳 出现第三种数据库或第二套命名约定

已经深、别动的部分（扫描的副产品）

  • 消息基座：IOutboxStore/IInboxStore 各两个适配器；重点在**六条真 broker 验收**（重试档位、死信、恢复、幂等、拓扑幂等），而且每条都做过反向验证。深度的来源不是抽象层数，是"违约时会红"。
  • 聚合版本号契约：一句话（Version 改变当且仅当可观察状态改变）+ 九个聚合各一条"改状态 +1 / 空操作不变"的测试。接口极小，语义极大——教科书式的深。
  • 跟踪器四脚本：check-tracker.ps1 23 组检查、check-format.ps1、assert-no-credentials.ps1、run-tests.ps1——它们把"规范"变成了会失败的东西，这是本仓最深的一处。
