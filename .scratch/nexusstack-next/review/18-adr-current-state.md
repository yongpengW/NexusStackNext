# 评审 18 —— ADR 里的"当前状态"（第 26 轮）

上一轮结尾说：地图刚证明过"没人查的文档会漂"，而 **ADR 比地图更少被读**。

## 结论先说：ADR 整体是**站得住**的，但有两处描述漂了

十四条架构 ADR（外加六个上下文各自的）里，绝大多数写的是**规则与决定**，
不是"现在代码里有什么"——那种写法**不会漂**。抽查了两条最像"存在性声称"的：

- **ADR-0004**（跨上下文只通过契约与集成事件）：通篇是"禁止……"与"每个发布事件的上下文**都需要**……"，
  是规则，不是现状。
- **ADR-0007**（版本化事件契约）："决定：每个集成事件在 `*.Contracts` 里**显式声明** `EventName`"，
  也是决定。

两条都**没有**声称那些东西已经存在。而**地图**恰好相反，这也是它漂的原因。

## 漂了的两处

### 一、ADR-0012 与 ADR-0013 **互相矛盾**

ADR-0012 写着：

> 参照仓库的配置中心里 `WorkerId=1` 是共享的。本仓现在是 **101–105**，逐个宿主不同。

而 ADR-0013 写着：

> 现在只有**一个进程**，只需要**一个** `WorkerId`。

实测：全仓只有一个——`WorkerId = 101`，在 `PlatformHost/Program.cs` 里。

**101–105 是"五个宿主"时代的数字。** ADR-0013 把五个平台能力合成一个宿主之后，
这句话就过时了，而**没有任何东西会发现两条 ADR 互相矛盾**。

已更正（保留原句与理由，说明数字为什么变）。

### 二、ADR-0014 把一个**有意的设计**写成了待修的缺陷

原文：

> `/gateway/openapi/sources` 与边缘的 Swagger UI **至今未受保护**，票据 10 记着这件事。

而 `AGENTS.md` 的端点清单写着：

> `/swagger` —— API 参考界面（**总是开**：它就在边缘上，**这正是要暴露的地方**）

**位置变了**：从"未受保护是个缺陷"变成"边缘的文档就该开着"。已更正，
并保留下仍然属实的另一半（`/gateway/openapi/sources` 确实未受保护）。

## 一个**刻意不建**的检查（以及为什么）

评审 16 给 `CONTEXT-MAP.md` 加了一条检查：**反引号里的标识符必须真的存在**。
自然想问：这条能不能直接搬到 ADR 上？

**不能。** 量了一下，ADR 里反引号包着但源码中不存在的名字有 9 个，**全部合法**：

| 未命中 | 它其实是什么 |
|---|---|
| `BackgroundServices` | **参照仓库**的分层名 |
| `nexus_identity` / `nexus_platform` / … | **数据库名** |
| `ConnectionStrings` | **配置节名** |
| `requireAuthentication` | `routes.json` 里的**字段名** |
| `OpenIddictTokens` | **被否决方案**的表名 |

`CONTEXT-MAP.md` 点的是**代码里的东西**，所以那条判据成立；
**而 ADR 合法地会点配置键、库名、以及"我们没选的那个方案里的表名"**——
这三类都无法靠文本判断"该不该存在"。

> **说清楚"这条检查不该建"，比建一条要么一直红、要么被掏空到没有意义的检查更有价值。**
> 后者正是这次 review 一直在抓的东西。
