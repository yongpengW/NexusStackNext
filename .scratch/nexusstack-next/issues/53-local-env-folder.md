# 53 — 本机环境变量目录 env/

Status: resolved

> 用户问："可以不可以直接在项目文件夹里创建个 env 文件夹，把配置中心的密钥放到 env 环境变量里"

可以，而且比手动在终端里设好。但**有一个必须先解决的风险**：
`env/` 一旦随模板分发出去，**每个用这个模板新建项目的人都会拿到你的密钥**——
那正是参照仓库栽过的跟头（票据 18）。

## 命名：用 `.dev`，不用 `.example`

用户要求："别用 env.example，用 env.dev"。

```
env/
  platform.dev    真实值：.gitignore 忽略 + 模板排除
  gateway.dev     真实值
  README.md       提交、随模板分发
scripts/
  run-host.ps1    -Init 生成骨架；不带参数则读文件、设进本进程、启动宿主
```

**`env/*.dev` 里放真实密钥，所以它被忽略、不进仓库。** 这一点我替用户选了安全的那一边：
反过来（提交 `platform.dev`）会把密钥写进 git 历史。

**"样板"的角色从文件挪进了脚本**：`run-host.ps1 -Init` 生成骨架。
理由：样板文件与填好值的文件**长得一模一样**，而"长得一样"正是把密钥提交进仓库的常见成因。

```powershell
pwsh -File scripts\run-host.ps1 platform -Init   # 生成 env/platform.dev
pwsh -File scripts\run-host.ps1 platform         # 启动
```

## 三道闸

| # | 机制 | 性质 |
|---|---|---|
| 1 | `.gitignore` 的 `env/*.dev` | 约定 |
| 2 | 模板 `exclude` 的 `**/env/*.dev` | 约定 |
| 3 | `assert-no-credentials.ps1` 断言生成物里**不存在任何 `*.dev`** | **会失败** |

第 3 条断言的不是"里面有没有凭据"，而是**这个文件根本不能出现在生成物里**——
因为本地文件本来就不该被模板扫描。

## 一个关于"两道串联防线"的发现

第一次做闸 3 的反向验证时，**它没有响**——原因是闸 2（排除规则）**先挡住了文件**，
生成物里根本没有东西可查。

也就是说：**第一道防线有效时，第二道永远不会响**，于是它看起来像一条无用的检查。

**正确的反向验证必须先打破第一道**：

```
移除 **/env/*.dev -> 重新生成模板 -> 检查精确报出 env\platform.dev 并 exit 1
还原排除规则     -> 恢复干净
```

这条与票据 45 那个"不会失败的测试"是同一类，但形态不同：
不是检查写错了，而是**它的触发条件被上游防线遮住了**。

## 过程中我自己的另外两个错误

**① 报告"已加"但规则没加进去。** 锚点缩进写成 14 空格、实际 12，`Replace` 静默无操作；
而那句"已加"检查的是**改之前**的状态。发现它是因为四条候选排除规则**全部泄漏**——
这个结果本身不合理。修法：**验证挪到写入之后**。

**② 骨架里 `# ---- 可选 ----` 与下一行粘在一起。** PowerShell here-string `@"..."@`
不含结尾换行，所以后续 `+=` 直接接上去了。已修并重新生成确认格式正确。

## 实测

```
env/gateway.dev 不存在        -> 明确报错 + 给出 -Init 命令，exit 1
-Init                         -> 生成骨架；再跑一次不覆盖
env/platform.dev 存在（3 项）  -> "环境变量来源：env\platform.dev（3 项，只作用于本进程）"
宿主日志                      -> "已接入 AgileConfig：AppId=nexusstack_platform，节点=…"
打破排除规则后                 -> 检查精确报出 env\platform.dev 并 exit 1
还原后                        -> 模板生成物 235 文件、8 规则、0 命中
```

## 一个连带发现

我给 `assert-no-credentials.ps1` 加的"配置里的真实 IP"规则（票据 48），
会拦下骨架里的真实服务器地址——**这是规则在正常工作**，
所以骨架里用的是 `http://your-agileconfig:8010` 这样的占位符。
