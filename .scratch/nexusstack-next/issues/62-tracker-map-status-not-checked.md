# 62 — 跟踪器检查器不查地图的状态列，于是它漂了

Status: resolved
Type: task
Labels: ready-for-agent
Blocked by: 61

> 收尾时把票据 49 标成 resolved，顺手看地图——**地图里它还写着
> `**needs-info**：等你设环境变量`**。而 `check-tracker.ps1` 报的是"跟踪器干净"。

## 缺陷

`check-tracker.ps1` 的第 5 项检查叫「map.md 索引与票据文件一一对应」，但它**只查存在性**：

```powershell
foreach ($id in $tickets.Keys) {
    if (-not $indexed.Contains($id)) { Add-Problem '地图索引' "票据 $id 存在，但 map.md 的票据索引里没有它" }
}
foreach ($id in $indexed) {
    if (-not $tickets.ContainsKey($id)) { Add-Problem '地图索引' "map.md 索引里有票据 $id，但没有对应的文件" }
}
```

**票据在不在索引里**查了，**状态对不对**没查。所以：

| 票据文件 | 地图显示 | 检查器 |
|---|---|---|
| `Status: resolved` | `**needs-info**：等你设环境变量` | **干净** |

**又是"一个不会失败的检查"**（票据 44、45、53、这个模式的第 N 次）。
它检查了一个真实存在的东西（索引完整性），于是看起来在守着什么——
但它守的那条与"地图是否说真话"无关。

票据 49 这次漂移**是我自己造成的**：票据 55/56 把它要做的两件事都做完了，
我更新了票据、忘了地图。**人工同步两个地方，迟早会漏一次**——这次漏在收尾。

## 修法

第 5b 项检查：**地图的状态列必须与票据的 `Status` 一致**。

地图是**给人看的摘要**，所以状态列允许写中文（`待开工`、`**needs-info**：…`）。
因此不做等值比较，只断言 **resolved 这一条双向一致**：

- 地图说 resolved、票据说别的 → 报
- 票据说 resolved、地图没说 → 报

**其余写法保持自由。** 查得太死会逼着人把摘要写成字段的副本，而那正好丢掉了摘要的价值。

## 验证

```
1. 加检查后先跑一次  → [地图状态] 票据 49 已是 resolved，但 map.md 的状态列写的是
                        '**needs-info**：等你设环境变量'      ← 精确报出真实漂移
2. 修 map 那一行      → 跟踪器干净：61 张票据 …
3. 反向验证：把票据 61 在地图里改回"待开工"
                     → [地图状态] 票据 61 已是 resolved，但 map.md 的状态列写的是 '待开工'
4. 还原               → 跟踪器干净
```

**第 1 步就是发现它的方式**——新检查第一次运行就报出了那个真实的漂移，
而不是"加了个检查，一直是绿的"。

票据 49 里写着"配置源接入（`AddAgileConfig`），并插到**环境变量之前**"，
而票据 56 已经证伪了这一点（`ConfigurationManager` 的重排不生效）。

不改它等于让一份已被推翻的结论继续以"已完成"的形态留在仓库里。
