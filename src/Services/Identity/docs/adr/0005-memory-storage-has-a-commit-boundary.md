# 开发存储也有明确的提交边界

Identity 的 Memory 仓储原来直接共享可变聚合，工作单元忽略提交判据。其他请求能看见尚未提交的禁用、授权与令牌状态，
失败后也无法撤回。这使 Memory 模式不能验证 [安全状态事实](0004-record-committed-security-state.md) 的原子性义务。

共享状态保留 singleton，仓储与工作单元使用同一 scoped 工作副本。User、Role、MenuTree、ApiResource、RefreshToken
提供显式独立快照；集合、节点、审计字段不共享可变实例，快照不复制待发布领域事件。领域类型不依赖存储或序列化包。

`SaveChangesAsync` 在事务内只暂存快照，工作单元在操作成功且提交判据允许后才发布。发布在同一临界区校验版本与唯一性，
准备行审计、完整最小事实批次及新 Outbox，然后一次替换共享状态。拒绝、取消或失败不发布部分状态与事实。
错误密码等明确保留的拒绝仍由应用命令管线决定，适配器不得自行把所有失败都回滚或都提交。

事务外保存保持对象跟踪，支持同一对象的后续修改；事实批次构造失败时可直接重试保存。版本/唯一性冲突与取消丢弃工作副本，
事务结束也清理工作副本，后续命令重新读取。不能自动重放一个已经过期的授权或令牌决策。

## Considered Options

- 继续共享可变实例，只在结果返回后发送消息：未提交状态已经泄漏，追加日志不能修复。
- 用反射或 JSON 复制领域对象：依赖私有字段布局与序列化配置，容易丢集合、版本和安全状态；采用明确快照。
- 让开发模式直接依赖 PostgreSQL：失去无库演示能力；保留开发适配器，同时继续以真实数据库验证生产行为。

## Consequences

`Identity:Delivery` 在两种存储上都由宿主显式组装。Memory Outbox 只保证进程内原子性，未交付记录会随进程结束丢失；
broker 确认后的消息可由中央稍后接纳，不能称为 Memory 来源的持久恢复。仅 Development / Testing 允许使用它。
工作副本复制本上下文状态，有明确的开发用途成本；生产容量与恢复验收继续使用 PostgreSQL。

`MemoryIdentityTransactionTests` 覆盖隔离、五类聚合创建、普通拒绝、错误密码的提交、事实批次失败、取消、同作用域重试、
重复保存、版本竞争、集合净变化及唯一约束。`MemoryIdentityAuditJourneyTests` 验证真实 HTTP 来源与 broker、中央查询的链路。
这些证据不替代完整故障/时间边界及容量治理。现有登录/刷新跨聚合写入的建模债务仍在，不能因工作单元原子提交而宣称符合单聚合事务。
