# 会话撤销版本由用户持有并持久化

状态：accepted。票据：[Identity 持久化运行模式与重启恢复](https://github.com/yongpengW/NexusStackNext/issues/22)。

会话版本是用户的安全状态。签发令牌从 User 读取，登出和刷新令牌重放检测推进它，随 Identity 命令事务提交。
授权通过 Identity 查询入口读取当前值；用户不存在、禁用或版本不匹配时拒绝。读取失败不接受令牌。
刷新令牌也保存签发时版本；撤销只修改 User 一个聚合，两类旧凭据均因版本不一致失效。
刷新先检查版本再检查重放，反复提交旧版本令牌不能撤销重新登录产生的新会话。

## Considered Options

- **提交后更新内存版本**：进程重启或提交后退出会丢失撤销，旧令牌重新有效。
- **单独把版本放 Redis**：需要额外保证数据库与 Redis 双写一致，缓存丢失也不能恢复成初始版本。
- **User 持有并映射数据库列**：复用已有存储适配器和事务；增加每次受保护请求一次读取，换取可恢复的权威状态。

## Consequences

删除只有 Identity 消费的共享 ISessionVersionStore；不为未来消费者保留另一份权威状态。
SessionVersion 与乐观并发 Version 各司其职：前者改变会话有效性，后者保护整个用户状态。
本决定替代 ADR-0017 中“提交后更新本进程会话版本”的部分；权限缓存仍在提交后失效。

撤销检查目前只覆盖 Identity 受保护端点。其余上下文的认证契约、跨实例权限缓存失效另行设计。
登出及重放撤销已收敛为 User 单聚合事务。正常登录、正常轮换仍有 ADR-0017 记录的跨聚合写入债务；本轮不宣称解决所有聚合边界。
