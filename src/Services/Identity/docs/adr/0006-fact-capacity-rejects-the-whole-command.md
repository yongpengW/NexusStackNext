# 审计事实容量不足时拒绝整个 Identity 命令

Identity 使用所属数据库的持久容量账本，语义与 [Platform ADR-0002](../../../Platform/docs/adr/0002-setting-fact-capacity-shares-the-business-transaction.md)
一致：100,000 条、正文总量 256 MiB、单条正文 16 KiB；待投递、死信和保留中的已确认事实都占用容量。
迁移锁住来源写入、回填当前占用并安装事务触发器，额度更新、事实批次和业务状态共同提交或回滚。
清理已确认且过期的副本才释放占用；事实 ID、契约、发生时刻和正文不可原地修改。

Identity 的特殊边界是一个命令可能产生多条最小事实。例如首次创建菜单含“建树”和“新增节点”，
只剩一个额度时不能保留第一条并丢掉第二条，也不能创建没有完整事实的菜单树。
存储层先让 EF 完成失败清理，再把精确的数据库容量拒绝转为应用端口的 `IdentityAuditCapacityException`。
事务回滚及跟踪器清理完成后，命令装饰器返回稳定 `identity.audit_capacity.exhausted`；HTTP 映射为 503。
其他保存异常保持原有行为，不把任意数据库错误伪装成容量问题，异常中不携带数据库诊断或连接配置。

容量失败不触发提交后的权限失效。成功改变授权后才失效；重复分配角色或菜单属于空操作，
不新增事实、不增加版本，也不额外失效缓存。错误密码原本属于“拒绝但保存安全变化”，
当来源容量不足时仍须整体回滚，不能假装失败计数已经保存；容量恢复后继续返回凭据错误并保存真实失败计数。

`HostIntegration.Tests/IdentityFactCapacityTests` 通过真实 HTTP 验证整批容量、业务/事实回滚和后续请求恢复；
恢复使用失败前确定的绝对额度，避免用失败后的计数计算额度而掩盖占用泄漏。
`Identity.IntegrationTests/IdentityFactCapacityTests` 经 ISender 验证同作用域重试、权限失效、授权空操作及错误密码路径。
测试夹具的 TRUNCATE 在同一测试事务内重置占用和默认策略；这不是产品维护入口。

Memory 对等准入、可审计策略调整/容量诊断和专门恢复仍在 #64 中。两个上下文的行为证据支持
将容量映射及冻结的触发器协议提取为共用实现，见[系统 ADR-0025](../../../../../docs/adr/0025-context-owned-fact-capacity.md)；
各自迁移、事实契约选择和错误到 HTTP 的映射继续归各上下文所有。
这一实现没有解决 Identity 既有令牌流程的跨聚合事务债务，也不代表多机吞吐量或高可用验收。
