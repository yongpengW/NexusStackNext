# 设置键的格式在构造时校验

`SettingKey` 在**构造时**校验格式，非法键根本构造不出来。因此通过 HTTP 传入一个坏键，
得到的是 **400**（请求有误），而不是一个"查不到、返回空值"的 200。

## 为什么

配置读取是 Platform 存在的理由，而它最常见的故障不是"值不对"，是"键写错了"。

如果键只是一个字符串，坏键的后果是**静默的空结果**：调用方拿到 null，
分不清"没配过"和"键拼错了"。这类问题的排查成本极高——它看起来一切正常。

把校验放进键的构造，坏键在**进入领域之前**就被挡住，并且带着"格式不对"这个事实返回。

## Considered Options

- **键就是个 string**：实现最省事，代价是每个读取点都要自己判断"这是没配还是拼错"。
- **构造时校验（parse, don't validate）**：合法键这个事实**由类型承载**，
  于是下游任何地方都不需要再检查一遍，也不可能传入未校验的值。

## Consequences

- 运行时可观察到：`GET /api/platform/settings/<非法键>` 返回 **400**（已实跑验证）。
- 与 ADR-0010（默认拒绝）同一取向：**宁可响亮地拒绝，不要静默地给一个看起来正常的结果。**
- 代价：将来若允许某种"宽松匹配"（如通配符键），必须在这里显式放宽，
  而不是靠调用方各自实现——那正是这类规则腐烂的方式。
