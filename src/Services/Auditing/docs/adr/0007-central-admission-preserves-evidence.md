# 中央容量接纳保留已有证据

状态：接受。依据：[中央审计有限接纳与容量诊断](https://github.com/yongpengW/NexusStackNext/issues/156)，父票[业务事实审计覆盖与容量治理](https://github.com/yongpengW/NexusStackNext/issues/64)。

来源副本的容量与已交付清理不能限制中央调查库增长。中央事实和操作观察各使用有限记录额度；
开始、结束观察分别占一条。额度满时不逐出旧证据、不删除 Inbox，也不把新消息判作无效消息。
相同消息的重复投递仍确认，内容/阶段冲突仍按原契约拒绝；新消息以存储暂不可用交回 broker 保管。

PostgreSQL 的技术计数账本与所属记录、Inbox、指纹在同一事务中更新；计数不是新的业务聚合，
没有伪造的 CreatedBy/UpdatedBy。增量迁移持表写锁回填已有数量，再安装 INSERT/DELETE/TRUNCATE
计量触发器。普通接纳只原子更新对应池的一行，不扫描事实或观察表。删除/清空计量只是账本一致性，
不提供删除入口或授予清理资格。迁移历史与原指纹算法保持不变。

接纳和容量读取有有限等待并支持取消；重试策略也共用同一总预算。SQL 配置只在当前事务有效，
不污染连接池。事实与观察是两池，调查时间窗口不影响用量；降低上限不会删记录或产生负的剩余额度。
配置上限属于本实例；同库生产副本必须一致配置，滚动调整期间只保证不超过参与写入实例的最大上限，
不声称是可在线修订的全局策略。上限不是数据库磁盘字节配额，不能代替磁盘监控和归档。

只读容量调查独立授权并抑制操作日志，防止诊断产生诊断积压。满容量在独立日志诊断中降级；
不会因此从业务 ready 摘除仍可工作的业务宿主。既有业务事实不自动删除；观察保留、归档校验、
删除资格及中央去重证据寿命继续由父票处理，本决定不宣称完成归档或永久幂等压缩。

触发器与其写入共用事务的语义依据 [PostgreSQL 触发器文档](https://www.postgresql.org/docs/18/trigger-definition.html)；
锁等待与语句超时的区别见 [连接配置文档](https://www.postgresql.org/docs/18/runtime-config-client.html)。
