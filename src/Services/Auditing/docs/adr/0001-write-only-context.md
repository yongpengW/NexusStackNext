# Auditing 是只写上下文

> 状态：已由 [ADR-0002](0002-committed-facts-and-controlled-investigation.md) 取代。下文保留历史取舍，不再描述当前 HTTP 契约。

`AuditEntry` 是**追加写、永不修改**的。因此 Auditing 没有对外的业务查询端点。

访问 `GET /api/auditing/entries` 得到 **405**（不是 404）——那条路径上现在有写入口
（`POST`），所以框架的回答是"这条路不通"而不是"没有这条路"。
两者都是拒绝，**405 更准确**：它说明这条路径是被有意占用的。

> **2026-09-29 更正。** 本 ADR 原文写的是"得到 404 是**故意的**，不是没做完"。
> 那句话在写下时是真的（当时 Auditing 还没有任何端点），在票据 37 给该路径加上写入口之后
> 就变成了假的。
>
> **决策一个字没变，但它描述的可观察事实变了。** 这类句子最危险的地方正是这里：
> 读起来像结论、像承诺，而且曾经确实是——没有任何东西会在它过期时提醒你。

## 为什么

审计数据的读者不是业务系统，而是人：出了事去查"谁在什么时候改了什么"。

把审计记录接进业务查询路径会带来两个后果：一是审计表被当成普通业务表 JOIN，
二是"为了排查方便"逐步给它加索引、加缓存、加分页，最后它变成一张和业务表一样热的数据——
而它本该是一条只增不减的流水。

## Considered Options

- **提供业务查询端点**：用起来方便，但审计数据的访问路径应该走**受控通道**。
  真要查，应当从数据仓库或专用查询服务走，而不是从业务 API 走。
- **只写**：业务侧无法误用，代价是排查时要换一条路径。

## Consequences

- 五个上下文里只有 Auditing 是只写的。这条差异写在 `src/Services/Auditing/CONTEXT.md` 的词表里，
  否则下一个人会把它当成"查询端点还没做"。
- **写入路径有两条，而这一段此前只写了一条。** 原文是"事件进入是唯一的写入路径"——
  那句话在票据 37 给 `/api/auditing/entries` 加上 `POST` 之后就不再成立
  （**同一份 ADR 的正文里就承认了那个入口**）。第 29 轮 review 更正：

  | 路径 | 状态 | 谁能用 |
  |---|---|---|
  | **集成事件**（`OperationPerformed` 一类） | **还没建**——事件总线与发件箱已就绪，但**没有生产者** | 各上下文 |
  | `POST /api/auditing/entries` | 已实现 | **进程内 / 运维**——**网关没有 `auditing` 路由**，经边缘不可达 |

  **"经边缘不可达"是有意的，而且此前没有被写下来过。** 它决定了这条端点在部署上怎么被使用
  （只能从内部或运维通道打），而**"没写下来"与"忘了配路由"从外面看是一样的**。
  （核对过：五个模块里只有 Auditing 的前缀没有网关路由。）

- `AuditEntry` 没有修改方法——这不是"还没写"，是**不打算有**。
- 这条决定与架构不变量 1（上下文独占数据）叠加：审计数据不参与任何跨上下文 join。
