# 事实携带有语义的关联客体

只有聚合标识与动作不足以回答“谁的令牌被消费、授予了哪个角色”。选择由来源的明确契约提供有语义的关联客体，
中央记录其上下文、类型及内部标识，并允许按三者精确调查。来源消费适配器验证允许的动作与关联类型组合；
不能从原始请求中自动挑字段，也不能读取业务表补齐。代价是逐项定义并验证事实，而收益是日志不依赖业务对象仍存在或当前关系未改变。

关联参与内容指纹，重投不得更换关系；缺少关联的旧事实保持原样及原指纹，不用当前业务状态补造历史。

权限集合采用逐项成员差异，每条事实只引用一个客体，避免任意请求字典、无界数组或截断后缺失部分变更。
同次提交可能有多条事实，均标识聚合的最终提交版本并与业务同事务保存；中央交付仍是最终一致，
暂时只看到其中一部分不能被解释为该次提交只有这些变化。来源容量策略还须约束整次提交的记录总量，
该项治理在当前票据中尚未完成。
