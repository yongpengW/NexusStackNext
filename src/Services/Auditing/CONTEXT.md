# Auditing

审计上下文：保存已提交业务事实与操作执行观察，供受权人员调查谁在何时对什么做了什么。观察到一次请求结束不证明业务提交，调查不可用也不等于来源业务不可用。

## Language

**AuditEntry**:
一条已提交业务或容量治理事实的不可变记录。它表达已经成立的变化，不表达请求尝试。
_Avoid_: 请求日志、操作观察、通用记录

**AuditFact**:
来源已经提交的最小事实，包含动作、客体及其版本、Actor、发生时刻与关联标识。普通事实不包含完整业务字段值；容量治理仅追加固定结构的前后数值额度。
_Avoid_: 请求尝试、操作意图、原始载荷

**AuditCapacityPolicyChange**:
来源已经提交的容量调整数值：请求身份、策略版本、固定理由及前后三个额度。
当前 Actor 和执行关联仍属于外围 AuditFact；来源、动作与客体由具体 Contracts 的接纳适配器固定。
这种变化必须有完整且合法的数值，不能只保存 changed 标题。普通业务事实没有该值对象。
_Avoid_: 任意 JSON、请求正文、完整业务参数、控制池当前状态

**AuditExecution**:
一次已提交事实所属的执行及其原发起关系。执行来源和事实所属上下文可以不同；即使操作观察缺失，
事实仍独立成立。没有来源证据时不补造关联。
_Avoid_: 当前操作者、提交凭据、完整操作记录

**Operation**:
由受信来源分配标识的一次执行，例如一次业务 HTTP 请求。它可能被受理、拒绝、取消或中断，业务提交需要另有 AuditFact 证明。
_Avoid_: 业务事务、消息、审计事实

**OperationObservation**:
关于同一次 Operation 开始或结束的不可变观察。它说明来源观察到了什么，不推断未观察到的执行结果。
_Avoid_: 成功事实、业务提交、最终状态通知

**CentralAdmissionCapacity**:
中央可继续接纳的事实与观察记录额度，两者分别计算。开始和结束观察各占一条，调查窗口之外的记录仍占额度。
额度耗尽不授予删除已有证据的资格，也不证明未接纳消息永久无效。
_Avoid_: 保留期限、归档证明、磁盘可用空间、来源积压

**Started**:
来源观察到 Operation 开始的证据。它不能证明业务已受理或已提交。
_Avoid_: 已执行、处理中保证

**Finished**:
来源观察到 Operation 结束及其结果的证据。HTTP 请求结束或受理并不表示异步工作已经完成。
_Avoid_: 业务完成、提交成功

**Unconfirmed**:
调查时尚无 Finished 证据的操作结果。它可能源于仍在执行、交付延迟、采集失败或进程中断，不能自动判成成功、失败或取消。
_Avoid_: 已失败、已成功、一定正在执行

**Action**:
发生了什么的稳定名称，例如 `identity.user-registered`。动作名称不是展示文案或任意请求内容。
_Avoid_: 操作类型、动作说明、日志消息

**Subject**:
被操作的客体（类型与标识）。它回答“对什么做了这件事”，不包含客体的完整内容。
_Avoid_: 对象、请求载荷、参数快照

**AuditSubjectReference**:
已提交事实中另一个有明确业务关系的客体，例如 RefreshToken 所属的 User。
上下文、类型和内部标识共同确定它；该关系描述发生时的事实，不承诺客体现在仍存在。
_Avoid_: 原始参数、显示名称、当前状态查询、授权凭据

**Actor**:
当前这次执行的人或系统身份。没有已认证用户时用户标识为空，不借用原发起人的身份。
_Avoid_: 自报用户、原发起人、占位帐号

**Initiator**:
引发后续执行的原发起人。它与当前 Actor 可以不同，仅有委托关系不能证明当前执行者就是原发起人。
_Avoid_: 当前操作者、当前认证身份

**Source**:
对记录内容负责的受信来源。AuditFact 标识来源业务上下文，OperationObservation 标识观察执行的来源宿主。
_Avoid_: 客户端来源、自报来源

**ExecutionOrigin**:
引发后续工作的直接操作、根操作及原发起关系。相同业务请求重投时沿用最初受理的来源，不能把重投人改成原发起人。
_Avoid_: 当前执行者、授权凭据、任务幂等键

**SourceJournal**:
来源端已经接受、等待可靠交付的 OperationObservation 记录。它的存在证明来源曾保存观察，不能证明调查端已收到，也不能证明业务提交。
_Avoid_: 业务 Outbox、中央记录、业务事务

**RecoveryReceipt**:
一次来源消息恢复与其控制记录共同提交的不可变凭据。保留期间，相同请求 ID 与相同内容重放原凭据；
它证明曾重开投递预算，不表示消息目前仍待投递，也不是原业务提交事实。源消息清理不删除该凭据。
固定 `RetainUntil` 是最早可清理时间；调整配置只影响新凭据，清理提交后结束该请求的历史幂等对照。
_Avoid_: 当前交付状态、操作观察、业务审计事实

容量按同一来源存储保留的记录数及载荷字节计算，已交付和死信在清理前仍占额度。
见 [来源容量](docs/adr/0005-source-journal-capacity-is-bounded.md)；容量耗尽的新观察明确拒绝，已有证据不被逐出。

**ExecutionRole**:
一次操作观察的是 HTTP 入口、代理转发、独立命令、实际任务执行、计划裁决、恢复还是消息消费。代理返回成功只证明转发结果，不能计作另一次独立业务提交；消息受理、调度登记与后续计算是不同执行。消息消费使用固定事件名与消息 GUID 作为客体，重复投递各有操作标识，不伪造任务或租约。
_Avoid_: 业务来源、权限角色、提交状态

**CorrelationId**:
帮助调查关联多次执行的标识。它可以来自调用方，既不证明操作者身份，也不决定两条消息是否重复。
_Avoid_: 授权证据、OperationId、幂等键

**OccurredAt**:
来源观察到执行或业务事实发生的时刻。它不是消息到达调查端的时刻。
_Avoid_: 接收时间、到达顺序

**RecordedAt**:
Auditing 接收并登记记录的时刻。它与来源的 OccurredAt 分开，不能作为业务先后顺序的证明。
_Avoid_: 操作时间、业务提交时间
