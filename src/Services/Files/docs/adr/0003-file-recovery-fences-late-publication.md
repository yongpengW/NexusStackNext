# 回收须同时阻止活跃写入和迟到的元数据提交

上传持有存储写入保护直到元数据保存结束；回收取得同一保护后，在数据库中确认没有引用并持久登记退役句柄，再删除字节。元数据保存和句柄退役使用同一把事务级数据库锁，保存拒绝已退役句柄，从而覆盖进程退出后数据库语句仍可能继续执行的窗口。

## Considered Options

- 仅按文件年龄清理：长暂停的上传仍可能恢复执行，年龄不能证明没有写入者。
- 文件锁加一次引用查询：能挡正常上传，但客户端断开后数据库提交可能还在执行；一次没有查到不能证明它不会稍后提交。
- 写入保护与持久退役标记：存储锁排除活跃写入；事务锁序列化登记与退役；退役记录阻止随后才取得事务锁的保存。代价是每个被回收的孤儿句柄保留一条很小的持久记录。

## Consequences

未知提交结果不立即补偿删除。回收在数据库不可用或退役提交结果未知时保留字节，后续重试。删除已有文件则使用文件聚合自己的待清理状态，每份文件独立提交；404 不能证明物理字节清除完成。

存储句柄永不复用，退役记录不自动过期；没有证明旧写入者已不可能恢复之前，时间本身不能作为删除退役记录的依据。该协议是本地存储适配器的恢复约束，对象存储需另行提供等价的写入保护能力。

本地句柄同时绑定目录中的持久存储身份。空目录替换、挂载丢失或者改配路径不能被解释为“原字节已经清除”；恢复原目录及其身份文件后才能继续确认删除。单个孤儿的 I/O 故障保留扫描进度，避免永久阻塞其后的候选。
