# 私有文件由归属者访问，元数据由 Files 持久保存

文件默认归有效会话中的归属者私有，根账号没有隐式越权下载能力；Files 在独立 schema 保存元数据并自行迁移。这样重启不会丢失字节的授权依据，代价是下载同时依赖当前身份校验、元数据与字节存储，任何一层不可用都不能放行。

## Considered Options

- 保留内存元数据：部署简单，但进程重启后磁盘字节失去归属和可查询标识，无法兑现已成功的上传。
- 将空归属解释为公开或允许根账号读取全部文件：方便运维，却把私有文件授权变成隐式例外。公开分发与管理授权须另行显式设计。
- 独立持久元数据：可与其他平台上下文共用物理库，但只读取 Files 的表；普通启动检查迁移，独立命令执行迁移。

## Consequences

内存模式只用于开发测试，也必须遵守独立快照与版本比较的提交协议。HTTP 不返回存储句柄；下载通过已授权的文件端点，以附件响应并禁止缓存及内容类型嗅探。

数据库和字节存储无法共享原子事务；持久化并不自动解决写入孤儿与删除中断，恢复协议在票据 #36 中单独验收。
