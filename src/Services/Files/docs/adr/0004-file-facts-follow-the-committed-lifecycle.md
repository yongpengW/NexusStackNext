# 文件事实跟随实际提交的生命周期

Files 仓储返回独立快照，保存时重新读取本上下文的原状态并校验版本，明确映射生命周期差异，与元数据同事务写入 Files Outbox。
不能用 Attach 后的属性修改标记判断变化：现有保存将整行标记为修改，那些标记不证明字段真的改变。
代价是每次更新多一次本上下文读取；最终 UPDATE 的版本条件仍阻止读取之后发生的并发覆盖。

登记、存储完成、请求删除、清理延期与字节移除分别使用固定动作。同一次上传可以同时提交登记和存储完成两项事实，
它们具有同一个最终聚合版本。重复状态不增加事实，事实写失败使整批事实与元数据一起回滚。
保存的所有失败路径清理跟踪状态，允许同一仓储作用域在确认失败后重试。

`StoredFileCommittedV1` 只携带文件标识、动作、版本、当前执行者与安全执行关联，不携带文件名、字节、句柄或下载地址。
HTTP 返回删除成功和字节实际移除是不同证据；审计消费者不能靠查询 Files 的表推断或补造缺失历史。
孤儿句柄退役属于恢复协议的证据，不冒充某个 StoredFile 被删除。

删除请求受理时由应用入口捕获安全执行来源，仓储只在首次成功提交删除状态时保存它，后续恢复与重复请求不覆盖。
来源与删除状态、事实共用事务和版本条件；来源未知保持未知，不从 Owner 反推发起人。
来源属于应用执行关联，存于 Files 的可空 JSON 列，不进入领域聚合，也不从审计库反查。
Memory 适配器在同一临界区遵守相同的首次提交规则，并原子提交元数据、行审计和整批事实。
共享状态为 singleton，仓储为 scoped，以读取当前调用身份；先构造完整事实批次与快照，再检查取消并提交，
构造失败不修改共享状态。后台系统身份不继承请求用户，空操作不刷新行审计字段。
两种适配器复用事实映射与宿主 Files Outbox 投递器；Memory 只保证进程内原子性，不保证未交付事实在重启后恢复。

每次后台恢复以文件标识描述独立 `recovery` 执行，不借用任务租约或计划裁决。
延期为 `deferred`，确认清理为 `completed`，异常和取消保持原异常传播并留下相应观察；
空扫描不产生文件操作。执行观察不替代事务事实，重启后事实的当前操作指向本次恢复，根关联仍指向原请求。
HTTP 内联清理属于当前 HTTP 操作。孤儿扫描不伪造文件标识，仍由恢复工作器报告诊断故障。

`MemoryFilesCommittedAuditTests` 验证 HTTP 生命周期、批次构造失败、取消、同作用域重试、跨作用域版本拒绝、
系统恢复身份与首次删除来源；真实 RabbitMQ 旅程证明来源结束后仍可接收已交付的消息。
PostgreSQL 容量使用[系统 ADR-0025](../../../../../docs/adr/0025-context-owned-fact-capacity.md) 的上下文独占账本：
登记与存储完成整批准入，拒绝时不发布部分元数据或事实。同一仓储作用域清理失败跟踪状态后可重新保存。
删除申请容量不足时不改变文件可见性；删除已受理但清除完成事实未能保存时返回待恢复，保留最初删除来源，
不把可能已经完成的字节操作认作元数据已确认。已确认事实的保留期清理才释放占用。
Memory 容量已通过[四个平台 Memory 事实容量与整批原子恢复](https://github.com/yongpengW/NexusStackNext/issues/80)验收。
四个平台的 Memory 共用写锁预算已通过[所属等待预算 #96](https://github.com/yongpengW/NexusStackNext/issues/96)验收。
事实消息的专用条件恢复由[六来源恢复 #103](https://github.com/yongpengW/NexusStackNext/issues/103)实施；
Files 已接入所属双存储协议，但完整故障矩阵及六来源最终资格仍需验收，不改变本文的字节恢复边界。
