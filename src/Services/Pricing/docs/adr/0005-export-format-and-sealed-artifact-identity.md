# 导出格式属于请求，实际字节身份属于原封存成果

2026-10-10，承接 ADR-0004 与票据 #57。

用户选择 CSV 或 XLSX 时接受的报价观察相同，但请求含义不同。格式与格式版本、列版本一起进入规范化请求；同用户和请求身份改格式拒绝。省略格式仍采用 CSV，既有 CSV 规范化文本保持逐字兼容。

冻结观察继续以精确 CSV v1 文本计算版本化快照摘要。XLSX 的 ZIP 元数据可以让同一观察生成不同字节，所以另外保存唯一成果的实际摘要和长度。在当前有效生成代次选定候选时，实际字节身份与发布意图在同一个聚合事务中保存；增量迁移为已选定的旧 CSV 回填原快照摘要与长度。

恢复先查询原 UploadId。已封存的原候选直接选定，不重新渲染，也不要求当前临时目录可写。只有缺失或尚未封存的候选才尝试生成；尚未封存但已登记摘要的候选只接受完全相同字节，摘要不符明确停在 candidate_bytes_conflict，保留原身份。此时新委托使用新 RequestId；不以新 UploadId 或新字节覆盖未知结果。已进入 Publishing 的恢复只交付原 FileId 与 PublicationId。取舍是少量未封存的 ZIP 身份冲突需要重新委托，换取原身份不会静默改内容或留下重复发布成果。

XLSX 适配器留在 Pricing Infrastructure，公开生成端口及 Files 协议仍在原边界；没有第二个导出上下文消费者前不抽出共享报表引擎。固定文本单元格保留 UUID、Int64 和四位小数，不伪装成 Excel 可无损运算的数字。代价是使用者需要自行选择数值转换与舍入。

候选关闭、已选定、已发布或已删除历史都不能经迁移降级被遗忘。新迁移在丢弃格式列前锁表并拒绝任何导出历史，避免逐步降级先丢掉实际字节身份，随后才被旧迁移拒绝。
