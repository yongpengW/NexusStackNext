# 普通定价查询使用可恢复失效与受保护回填

Pricing 的查询缓存采用最终一致性。聚合改变时，在同一个数据库事务内登记失效意图；后台删除共享 Redis 键后确认该条意图，失败与进程退出都可重试。任何命令与任务执行都不依赖 Redis。权限判定不使用此缓存。

查询命中不访问数据库。未命中时先取得该键的随机填充令牌，再从主库读取当前快照；Lua 只在令牌仍相同时保存结果。失效、过期、淘汰和清空都会撤销旧令牌，迟到回填不能重新创建键。独立宿主共享命名空间，不建立本机一级缓存。

取舍：提交成功到失效传播之间允许短暂旧值，固定 TTL 不随读取续期。Redis 切换导致已确认删除回滚时仍靠 TTL 收敛；这不是强一致读取。需要强读的业务应直接查询数据库。每次查询数据库 Version 再选择版本键虽可提供更强可见性，但本样板是单行查询，该方案增加往返且不能减去数据库读取，故不采用。

命名空间包含部署及数据库世代，数据库恢复后统一轮换。客户端只操作自己的键，不修改共享 Redis 的全局容量配置。回源每宿主限制并发、没有等待队列并有时间预算；超限返回 503。首次只有 Pricing 使用，不把模块提前移入 BuildingBlocks。
