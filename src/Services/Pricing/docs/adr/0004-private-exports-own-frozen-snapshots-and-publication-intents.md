# 私有导出保存冻结快照并承担唯一发布义务

Pricing 的 Export 是独立业务聚合，持久保存用户范围内的请求身份、完整规范化内容、摘要规则版本及最多五千行的精确有序报价值。导出读取 Pricing 自己的权威报价，后续执行和重放只使用这份快照；保存筛选再查活表会在重试中改变用户已接受的成果，Redis 投影也不能承担一致观察。

接受使用 Read Committed 短事务：先以用户与请求串行化并查询原身份，再用一条有行数上限的 SELECT 冻结报价。一个语句拥有一致 MVCC 观察，观察时间来自该语句的数据库时刻；使用跨多个分页的长期事务会把冻结变成无界工作。预先建立 Repeatable Read 快照再等待幂等锁，则可能在另一接受者提交后仍看不见它。请求摘要和固定 CSV 快照摘要独立版本化，完整规范化内容保留冲突判定；提交响应未知只允许以原身份恢复。

不可变行作为有界聚合值保存在 JSONB 中，不建立对活报价的导航或外键。取舍是每份快照占据独立存储；它换取报价后续变化、删除及缓存故障与已接受成果的隔离。JSON 仅在服务内按 Guid、Int64 和 decimal 读写；CSV 直接生成精确文本，列序、UTF-8、CRLF 和数值格式固定，不包含任意用户文本。CSV 精确文本不能保证 Excel 的自动类型推断保留长整数。

Files 通过受认证 HTTPS 提供暂存和发布裁决，不共享存储目录或用户令牌。Pricing 将当前有效执行代次选定的候选与稳定 PublicationId 作为持久发布意图，在本地事务进入 Publishing；这个意图提交之后取消返回冲突。恢复者持续查询或重投同一意图，核对原描述和回执后完成导出，不更换候选或重新冻结。选择这一边界，是因为没有跨库持久撤销协议时，允许 Publishing 后取消会产生已取消但成果已发布的状态。

首次领取固定 UploadId，接管只更换执行代次。上传提交结果未知时，后续执行先查询并恢复同一候选；换一个候选会把真实已封存的字节遗留成重复成果。旧执行者即使完成同描述的封存，也不能凭旧代次选定发布意图。候选已经终态关闭时保留身份并明确停止，新导出使用新 RequestId。

发布回执的 PublishedAt / ExpiresAt 是外部历史，按 UTC ticks 保存全部 100ns 精度，避免另一数据库的时间列精度导致原回执重放冲突；本地接受、快照观察、租约和交付裁决仍使用 PostgreSQL 时间。增量迁移的回退先在同一事务取得表锁，再拒绝删除任何已经接受的历史，包括取消和其他终态；不能通过回退遗忘原请求或发布义务。

本决定扩展早期 ADR-0001 的单个报价样板：PriceQuote 继续拥有报价，Export 拥有快照与委托，每次写入仍只修改一个业务聚合。当前普通用户的操作授权沿系统 ADR-0028，后台是独立系统执行，归属用户只代表已接受委托。
