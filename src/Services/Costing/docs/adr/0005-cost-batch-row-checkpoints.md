# Costing 拥有批次输入与逐行检查点

批次沿用 PoS 的全量静态验证、原始位置和末条生效体验，避免整批多对象事务。
CostBatch、InputRow、Attempt 是 Costing 私有技术记录，不是新的业务聚合，也不放入 BuildingBlocks。
一个行事务只修改一个 CostSheet，同时保存子计算、所属变化事实、行结论和连续检查点。
接收只持久化不可变快照及稳定身份；不会预先改变成本对象。

JSON 上限、准确传输、静态错误、摘要 v1、身份重放、分页、取消/重试及配置见
[公开契约](../../../../../docs/costing-batch-import.md)。不存在第二个批次消费者，不创建共享框架。
SourceRow 表达用户原始位置，Sequence 表达输入次序；重复结论保存生效行的 Sequence。
金额规则复用 CostSheet 的规则，所有原始行必须先合法，再执行去重。

父执行权使用数据库时间、Epoch、LeaseUntil 和固定 MaxLeaseUntil。锁顺序是父批次 → 行/请求 → Item。
每行有总预算和更短的 SQL/锁等待预算，提交前重新检查原租约，不能用本事务的续租复活过期执行权。
解析及分段读取在短事务外，子计算及定价在导入事务外，停止本次执行不丢弃已提交检查点。
取消、失败、续租和终态都由父锁裁决，旧 Epoch 不留下尾行；最后一行完成优先时取消冲突。
技术失败有限重试；业务版本冲突只拒绝该行。Failed 条件重试保留位置，取消不会自动恢复。

批次和行身份永久保留至将来另定治理协议。子身份从批次及 Sequence 版本化派生，
受理时与手工请求及计划发生身份互斥，不能被更晚的手工或计划请求占用，即使批次已取消。
提交应答不确定时经公开查询核对；同身份重放不重复修改对象或产生第二个子任务。

Costing 的就绪检查只检查持久受理的依赖。MQ 属于后续 Outbox 交付依赖，单列 `/health/delivery`，
避免网关在 broker 离线时摘除仍能受理及查询的服务。日志诊断保持独立。
这不保证无限离线受理：所属审计事实容量和消息投递预算继续生效，需要分别观察积压与恢复。

迁移追加 Costing 私有表，不重写已发布迁移，不为旧单项任务编造批次来源。
输入中的业务冲突需新身份修正；Completed 只表示导入处理，不表示计算、broker ACK 或 Pricing 完成。
每段后台观察是独立执行尝试，保存受理关系；对象变化事实仅在所属行确实提交时产生。

验证用真实 PostgreSQL 行写失败、COMMIT 应答丢失、非空检查点接管及双向取消竞争；
真实进程在段内终止，网关观察混合结论，MQ 离线及恢复后 Pricing 原消息重放保持版本不变。
首版上限不是容量 SLO；文件适配、业务角色授权、导出及多机部署分别由后续票据处理。
