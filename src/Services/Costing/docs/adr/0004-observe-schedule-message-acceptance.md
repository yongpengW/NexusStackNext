# 计划消息消费保留独立执行证据

调度完成交付、Costing 接受委托和后台成本计算是三个阶段。原实现只保留接受回执和任务来源，
缺少每次消费尝试的记录；失败回滚时没有回执，重复投递也不能用原回执表达新的尝试。

复用已经由 Pricing 使用的消息执行观察端口，每次有效 ScheduleTriggeredV1 消费建立 message 操作，
固定动作 costing.schedule.accept，客体为固定事件名和发生消息 GUID。它不是 schedule 裁决或 task 租约，
不伪造这两类执行字段。信封与契约无效时不建立业务受理观察。

Inbox、内容指纹、稳定回执与可选任务继续在 Costing 本地事务内提交。首次接受为 accepted；
目标不存在或身份已被人工任务使用时，稳定回执为 Rejected，消息仍被确认，观察结果必须为 rejected。
同身份同内容重投为 duplicate，异内容冲突为 rejected 且不确认；异常与取消分别记录 failed / canceled。
业务拒绝回执也必须成功提交才确认消息，不能把拒绝保存失败当作稳定业务拒绝。

新任务保存首次成功受理操作作为直接来源，原调度操作作为父级，根操作与原发起人沿用消息内来源。
指纹仍使用原始消息，重投不能更换、移除或补造来源。旧任务保持已存关系。
消息没有执行来源时，新消费只有已知的本地操作；CreatedBy 继续表达委托，不能拿它补造缺失的发起关联。
观察作用域以系统 Actor 执行，不继承调用链中的用户，不改变原有委托与授权规则。

普通观察在独立 journal 中保存，业务提交失败不会撤销它；进程在提交前终止时只能保留 Started，
中央显示 unconfirmed。重投产生新操作，成功受理后任务关联新操作，不能补写旧操作为成功。
复用现有任务来源与观察载荷，无需新增 Costing 迁移。

完整旅程发现 HTTP 原请求未保存自身根字段，导致根查询只能返回后续步骤。新 HTTP 观察在两个阶段
保存已知的本地根标识及来源；旧记录不追填，跨 HTTP 代理仍按现有追踪关系调查。

ScheduledCostMessageOperationTests 验证并发去重、身份、稳定拒绝、异常/取消回滚、同作用域重试及来源跨重启。
ScheduledCostBusinessJourneyTests 用真实 RabbitMQ、HTTP 和进程终止验证未确认与恢复，以及区间/日历计划
在创建人注销后的完整调用关系。相同成本重算不改变业务版本，Pricing 的消息观察可为 skipped 而不产生新计算。
容量、死信恢复与保留治理仍由票据 #64 完成。
