## 2. 最小安全设计（由上述事实推导，尚未实测）

1. **TLS 先拒绝不可信证书，认证再限定生产者。** 内部 Kestrel HTTPS listener 使用 `AllowCertificate`，保持其他 JWT 请求可无客户端证书。`OnAuthenticate` 设置新的 `X509ChainPolicy`：`CustomRootTrust`、根白名单、已知中间证书 `ExtraStore`、`VerificationFlags=NoFlag`、当前系统时间、clientAuth 用途、`Online/ExcludeRoot` 吊销检查、`DisableCertificateDownloads=true`、正值 `UrlRetrievalTimeout`。保持默认 `ClientCertificateValidation`，不要一律放行后才交给 HTTP 处理器判断。Kestrel 已在 `SslStream` 构造时安装回调；不要在 `OnAuthenticate` 换成不同的 `RemoteCertificateValidationCallback`，运行时会拒绝冲突的回调。[Kestrel 源码](https://github.com/dotnet/aspnetcore/blob/v10.0.12/src/Servers/Kestrel/Core/src/Middleware/HttpsConnectionMiddleware.cs)；[运行时选项更新](https://github.com/dotnet/runtime/blob/v10.0.12/src/libraries/System.Net.Security/src/System/Net/Security/SslAuthenticationOptions.cs)
2. PlatformHost 在 `Program.cs` 显式注册命名 `AddCertificate` 方案，维持 `.AddAuthentication(JwtBearerDefaults.AuthenticationScheme)`。只给内部 Files 服务路由设置该方案的 policy 与 `RequireAuthenticatedUser`/生产者要求；不要把 Bearer 加进同一 policy，也不要由另一个授权属性把方案合并成并集。默认 JWT 注册、用户会话过滤器与公共 Files 路由仍走原链。[指定方案授权说明](https://learn.microsoft.com/en-us/aspnet/core/security/authorization/authorize-with-a-specific-scheme?view=aspnetcore-10.0)；[仓库基线组合](https://github.com/yongpengW/NexusStackNext/blob/0bbffdaae8a15db5761f811c3427c620d83b2398/src/Hosts/NexusStackNext.PlatformHost/Program.cs)
3. `OnCertificateValidated` 只以 **SHA256 叶证书指纹 → 已许可 Producer** 映射创建自己的最小 `ClaimsPrincipal`；未知指纹 `context.Fail(...)`，成功才 `context.Success()`。配置拒绝空根集合、格式错误/重复指纹、不支持的 Producer；额外拒绝 CA 叶证书、缺少明确 clientAuth EKU 或 digitalSignature 用途的凭据。轮换可允许两张证书映射同一个 Producer，但不能依赖 CN、issuer 文本、请求体或 header 自报 Producer。[框架验证事件位置](https://github.com/dotnet/aspnetcore/blob/v10.0.12/src/Security/Authentication/Certificate/src/CertificateAuthenticationHandler.cs)
4. 首版**不注册 `AddCertificateCache` 或其他 `ICertificateValidationCache`**，每请求重新建链、检查有效期与当前映射。Production 保持 `Online`、`NoFlag`；吊销、未知吊销状态、过期均不得忽略，也不能在 `OnAuthenticationFailed` 中改成成功。证书映射撤销与 CA 吊销是两条防线；Online 仍会使用平台有效的 CRL/OCSP 缓存，不能承诺 CA 发布吊销的瞬间全球生效。[处理器](https://github.com/dotnet/aspnetcore/blob/v10.0.12/src/Security/Authentication/Certificate/src/CertificateAuthenticationHandler.cs)；[Linux 吊销实现](https://github.com/dotnet/runtime/blob/v10.0.12/src/libraries/System.Security.Cryptography/src/System/Security/Cryptography/X509Certificates/OpenSslX509ChainProcessor.cs)
5. 不注册 `AddCertificateForwarding`/`UseCertificateForwarding`，不读取任何转发证书头；仅真实 Kestrel TLS 对等证书可认证。内部路径不加入网关路由，不发布业务 listener 宿主机端口；HTTP 请求即使伪造证书头也不得执行服务操作。内部协议不复用普通用户上传入口或用户 JWT。[官方认证的 TLS/转发边界](https://learn.microsoft.com/en-us/aspnet/core/security/authentication/certauth?view=aspnetcore-10.0)；[仓库部署不变量](../../AGENTS.md)

## 3. Pricing HttpClient、超时与 Linux

**客户端优先使用 `SocketsHttpHandler.SslOptions.CertificateChainPolicy`，保留默认远端验证。** 给 `SslOptions.ClientCertificates` 配自己的带私钥叶证书；配置固定 HTTPS Files 地址、限定服务端根、serverAuth 用途、`NoFlag`、已知中间证书。运行时从连接目标设置 `TargetHost`，默认仍检查主机名；不要设置 `IgnoreInvalidName`，不要覆盖 `Host`，不要使用恒真的远端验证回调。自定义根链不需要牺牲 SAN/主机名校验。[SocketsHttpHandler API 实现](https://github.com/dotnet/runtime/blob/v10.0.12/src/libraries/System.Net.Http/src/System/Net/Http/SocketsHttpHandler/SocketsHttpHandler.cs)；[目标主机来源](https://github.com/dotnet/runtime/blob/v10.0.12/src/libraries/System.Net.Http/src/System/Net/Http/SocketsHttpHandler/ConnectionPool/HttpConnectionPool.cs)；[名称检查开关](https://github.com/dotnet/runtime/blob/v10.0.12/src/libraries/System.Net.Security/src/System/Net/Security/SslAuthenticationOptions.cs)

建议初始预算（实施值，可调整）：链下载 2 秒、连接 5 秒、TLS 握手 10 秒、一次 HTTP 操作 30 秒；`AllowAutoRedirect=false` 防止内部服务操作被重定向到其他目标。`ConnectTimeout`、`PooledConnectionLifetime`、`SslOptions` 均由 `SocketsHttpHandler` 提供；握手默认已是 10 秒。若使用 `ResponseHeadersRead`，`HttpClient.Timeout` 只约束收到响应头之前，读取响应体必须继续传递有截止时间的取消令牌。[handler 源码](https://github.com/dotnet/runtime/blob/v10.0.12/src/libraries/System.Net.Http/src/System/Net/Http/SocketsHttpHandler/SocketsHttpHandler.cs)；[Kestrel HTTPS 选项](https://github.com/dotnet/aspnetcore/blob/v10.0.12/src/Servers/Kestrel/Core/src/HttpsConnectionAdapterOptions.cs)；[ResponseHeadersRead 超时语义](https://learn.microsoft.com/en-us/dotnet/api/system.net.http.httpcompletionoption?view=net-10.0)

**边界：`AddCertificate` 没有 `UrlRetrievalTimeout`/`DisableCertificateDownloads` 选项。** 它每请求新建的策略使用默认下载预算，不能把 TLS 的 2 秒策略或 10 秒握手期限说成这个步骤的上限。API 文档把零描述为无上限，而锁定版本的 Linux `ChainPal.OpenSsl` 将零转为 15 秒下载预算、最大 60 秒；按源码限定平台结论，不能把它扩成同步 `X509Chain.Build` 总耗时保证。最小首版保留框架 Online 校验，配置完整链并承认此预算差异；若验收要求**请求级**精确 2 秒吊销上限，需另做有明确边界的验证模块，不能偷偷改成 `NoCheck`。[认证选项全集](https://github.com/dotnet/aspnetcore/blob/v10.0.12/src/Security/Authentication/Certificate/src/CertificateAuthenticationOptions.cs)；[链策略默认值](https://github.com/dotnet/runtime/blob/v10.0.12/src/libraries/System.Security.Cryptography/src/System/Security/Cryptography/X509Certificates/X509ChainPolicy.cs)；[API 文档](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.x509certificates.x509chainpolicy.urlretrievaltimeout?view=net-10.0)；[Linux 10.0.12 下载预算](https://github.com/dotnet/runtime/blob/v10.0.12/src/libraries/System.Security.Cryptography/src/System/Security/Cryptography/X509Certificates/ChainPal.OpenSsl.cs)

Linux 实现确实支持 `CustomRootTrust`，自定义根替代系统根；根放 `CustomTrustStore`，中间证书放 `ExtraStore`/`AdditionalChainCertificates`，不要把依赖操作系统安装测试 CA 当成测试前提。macOS 忽略 `UrlRetrievalTimeout`，不能拿本机结果替代 Linux CI。TLS 连接复用不是每请求重新握手；请求认证不得信任“以前握手成功”或固定旧 `VerificationTime`。若要约束新连接的恢复行为，可显式关闭 `AllowTlsResume`；这不能替代每请求认证。[Linux 根信任实现](https://github.com/dotnet/runtime/blob/v10.0.12/src/libraries/System.Security.Cryptography/src/System/Security/Cryptography/X509Certificates/OpenSslX509ChainProcessor.cs)；[跨平台差异](https://learn.microsoft.com/en-us/dotnet/standard/security/cross-platform-cryptography)；[TLS 选项](https://github.com/dotnet/runtime/blob/v10.0.12/src/libraries/System.Net.Security/src/System/Net/Security/SslServerAuthenticationOptions.cs)

## 4. 实施后的反向验证建议

真实 Kestrel → HttpClient HTTPS 旅程使用每次测试临时 CA，分别签发带 serverAuth/SAN 的服务器叶证书与带 clientAuth/digitalSignature 的客户端叶证书。`CertificateRequest.CreateSelfSigned` 可建临时根；`Create(issuerCertificate, ...)` 返回不带私钥的叶证书，须接上自己的私钥。`SubjectAlternativeNameBuilder` 可加入 `localhost` DNS 与 loopback IP，连接 URI 必须匹配所用 SAN。[CertificateRequest 源码](https://github.com/dotnet/runtime/blob/v10.0.12/src/libraries/System.Security.Cryptography/src/System/Security/Cryptography/X509Certificates/CertificateRequest.cs)；[SAN 构造器](https://github.com/dotnet/runtime/blob/v10.0.12/src/libraries/System.Security.Cryptography/src/System/Security/Cryptography/X509Certificates/SubjectAlternativeNameBuilder.cs)

无 CRL/OCSP 的临时 CA 只在明确的测试组合使用 `NoCheck`；这只能证明链、身份与 TLS 旅程，不能报告“吊销已验证”。Production 不提供静默降级。独立吊销检查须有可控 CRL/OCSP 事实并验证 revoked/unknown 都拒绝；原始 TLS 无证书、错误根、过期、错误 EKU、同 CA 未映射证书、已移除映射、仅 JWT、伪造转发证书头均不得完成服务写操作。另验服务端错误根/错误主机名导致 HttpClient 失败，普通 JWT 端点仍按原协议工作。把 TLS 拒绝和 HTTP 禁止分开记录；客户端没实际发送证书时，403 只证明请求级拒绝，不证明握手校验已经拒绝那张证书。

## 5. Windows 实施验证与限制

`CopyWithPrivateKey` 的临时 RSA 凭据在本机 Schannel/SslStream 旅程遇到 credential acquire 失败；测试夹具改为仅在进程内导出 PKCS12并通过 X509CertificateLoader 重新导入，再取服务器 PEM 私钥，未安装 CA。已有 .NET 运行时问题记录支持此故障分类；当前可运行结论来自本机真实 HTTPS，不把旧问题扩展为所有平台保证。[运行时问题23749](https://github.com/dotnet/runtime/issues/23749)

`GeneratedFilesHttpsTests` 使用临时 CA、真实 Kestrel 与客户端证书，单项资格已通过根链与显式中间 CA、同 CA 未映射403、强制发送错误根后的 TLS 拒绝、已明确映射却过期/错误或缺少用途/CA 叶拒绝、普通 HTTP 和 JWT/伪造转发头拒绝。Production NoCheck 配置拒绝启动；Production Online 对没有 CRL/OCSP 的临时 CA 拒绝未知吊销状态。完整 Linux 及 dev 交付资格见 #149 的最新原生证据，这里不宣称实际 revoked 或生产 PKI 已验收。
