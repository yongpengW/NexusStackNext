# 本地测试负载所有权

共享 PostgreSQL 同时服务 AgileConfig。本地工程逐个执行，宿主测试进程内部串行；
显式4/2路仅在同一个所有者下调度已审核普通旅程，重操作单许可、特殊旅程独占，见
[受控并发](local-test-concurrency.md)。
跨工作区使用相同的系统临时目录与更新后的 `scripts/run-tests.ps1`，一次只运行一份。
独立临时目录仅用于不连接服务的外部 CLI 探针，不用于绕过真实测试保护。
CI 的四台托管 runner 各自拥有私有依赖，不共用这台数据库。

## 原子保护与状态

`test-ownership.psm1` 以 `FileShare.None` 原子打开系统临时目录下的
`nexusstack-run-tests.lock`，持有文件句柄直到运行结束。文件保留在原位置，
不会通过删除文件再创建来改变保护对象，也没有按年龄接管的路径。
第二份负载在进入构建、发现或测试前被拒绝。
首次使用以 `CreateNew` 原子建立文件；已有文件必须具有有效的 `idle` 状态。
已有的空文件、数组形式的根对象和协议字段也拒绝；版本必须是整数，`idle` 必须是单个字符串，
不能把损坏状态当成首次创建或正常完成，免得它获得接管资格。

文件中的 `active` / `idle` 是恢复状态，句柄才是运行期间的互斥。
`active` 记录所有者 PID 和进程启动时刻，PID 或文件年龄都不是接管依据。
正常返回的外部命令（包括非零构建 / 测试退出码）可以写回 `idle`；
命令中断时释放句柄但保留 `active`，因为父进程结束不证明子测试负载结束。
意外杀死所有者同样留下 `active`。异常或不兼容的状态拒绝启动。

## 拒绝后的恢复

遇到 `TEST_OWNERSHIP_REJECTED`，先检查原运行的工具 session、进程身份及其测试子进程。
日志不更新、调用没有输出、观察等待超时或文件超过两小时，都不是负载结束的证据。
仍有原负载时等它结束，保留唯一所有者约束。

若所有者异常退出，自动恢复保持拒绝；即使 PID 不存在或已被复用，也不会按 PID 接管。
必须确认原构建、vstest、testhost 及其宿主子进程全部结束，才能由操作者修复该恢复状态。
受控并发还须核对全部worker进程及其原生子负载；私有目录保留进程身份与返回记录。
记录检查依据，并在独占打开同一个保护文件后写回 `{"Version":1,"State":"idle"}`，
关闭句柄后再运行脚本。持有者仍活着时独占打开会失败，不能删除其保护文件继续。
无法证明负载结束时保留拒绝，不清理无关进程。

这是保守恢复：失去所有者的状态不会自动变绿。所有工作区须采用更新后的脚本，
旧脚本没有原子持有句柄，不能与新脚本混用后声称全机保护已生效。

## 验证

`pwsh -File scripts/check-test-ownership.ps1` 复制真实 runner 到两个临时工作区，
以外部 fake dotnet 和隔离的 TEMP / TMP / TMPDIR 验证跨工作区竞争、三小时的活跃保护、
成功及构建 / 测试失败后的释放、异常状态拒绝和父进程消失但外部负载仍存活时的拒绝。
异常状态包含已有的空文件、单元素和多元素根数组；首次创建的正向控制仍必须实际进入外部负载。
先证明外部负载实际进入，才接受拒绝结论；探针不连接数据库、Redis 或 broker。
探针清理仅针对它自己创建的进程，核对 PID 与启动标记后执行；
Linux 使用内核启动计数，Windows 使用 UTC ticks，复用票据 CLI 探针的身份模块。
统一 CI 门禁运行同一探针；Linux 实际语义必须通过该门禁验证。
