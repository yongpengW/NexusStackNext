# 宿主测试耗时与初始化复用

首轮已通过 [宿主测试提速：脱敏实时进度与共享库初始化复用](https://github.com/yongpengW/NexusStackNext/issues/112) 交付。
扩大复用与校准 CI 权重见 [扩大宿主旅程空结构复用并校准 CI 实测权重](https://github.com/yongpengW/NexusStackNext/issues/114)。
开发仍使用 `env/test.dev` 的共用 PostgreSQL，保留跨工作区原子所有权；显式普通旅程并发见
[共用测试库受控并发](local-test-concurrency.md)。下方#112/#114测量均为当轮串行模式；
CI 仍由四台独占依赖的 runner 执行，统一门禁核对完整发现清单与每项结果。

## 能看见的进度

`scripts/run-tests.ps1` 通过正常详细度的 console logger 接收已完成用例，实时打印工程、
完成数、结果、无参数的方法名与工程已用秒数。第一项、每 25 项、失败或跳过都会输出；
距离上次输出超过 30 秒时，下一个完成用例也会输出。长用例尚未完成时不会伪造完成数。
最后的计数读取 TRX，进度不是 CI 覆盖清单或最终结论。

原始异常、Theory 参数及原始控制台行不转发到普通输出。
TRX 与原始控制台诊断仅保留于系统临时目录下的唯一 `nsn-test-results-*` 目录，可能含敏感数据。
每个工程的 `.console.log` 逐行写入并刷新，负载运行期间即可在本机读取；不再等待整工程结束。
CI 上传的仍只有独立目录中的脱敏 shard JSON，不上传这些诊断文件。
`scripts/check-test-progress.ps1` 用外部 CLI 适配器验证真实 runner 在负载结束前报告进度，
并验证中英文输出、运行中的私有原始证据、参数和伪摘要脱敏、失败退出、所有权释放及未知工程拒绝。

过滤执行可以精确选择工程，避免为其他工程启动空测试进程：

```powershell
pwsh -File scripts/run-tests.ps1 -Configuration Release -NoBuild -Project HostIntegration.Tests -Filter 'FullyQualifiedName~SomeJourney'
```

`-NoBuild` 要求先构建当前源码；不传 `-Project` 仍执行全部工程。
工程名大小写精确匹配且必须唯一，错误名称失败。CI 分组禁止工程选择和用户过滤，
发现清单、完整执行与统一合并门禁保持一致。

本地可加 `-StopOnFailure`：xUnit 在首个失败后停止安排后续用例，当前在途工作仍正常返回，
runner 不再启动后续工程。原生失败退出、私有报告与所有权释放保留；失败早停不是完整通过。
全部健康时仍执行完整清单，CI 分组在读取配置或启动负载前拒绝这个选项。
依据：[xUnit StopOnFail](https://xunit.net/docs/config-runsettings#StopOnFail)。
`check-test-progress.ps1` 同时调用 `check-test-stop.ps1`：不连接任何服务的真实两工程 CLI 探针
验证后续用例与工程停止、异步 collection 夹具清理、全部健康时完整执行及 CI 提前拒绝。

```powershell
pwsh -File scripts/run-tests.ps1 -Configuration Release -NoBuild -StopOnFailure
```

## 普通旅程的初始化

`JourneyDatabaseTemplates` 是 xUnit collection 所有的测试装置，仅在确有 PostgreSQL 用例运行时创建。
平台、Costing、Pricing 各拥有惰性创建的自有模板。平台执行六模块真实 EF 迁移，
两个业务模板仅执行各自上下文的真实迁移；随后关闭自有模板连接并终止其残留会话。
它不接收业务写入，也不向宿主提供自己的连接配置。

普通旅程由该结构生成新的独立临时库。每个用例仍独占可写数据、业务连接池及故障开关，
按原有生命周期清理；collection 结束后逐个尝试清理所有已成功创建的模板，清理异常合并报告。
不缓存宿主、账号、业务数据或上次用例结果。
不同 CI runner 各自创建模板，不跨 runner 或跨运行共享。

复制显式使用 `WAL_LOG`，适合小型模板，避免 `FILE_COPY` 强制共享服务器 checkpoint。
原库必须没有连接；目标显式允许连接。数据库级配置与权限不会随模板复制，
本装置没有依赖这类额外设置。依据：[PostgreSQL CREATE DATABASE](https://www.postgresql.org/docs/18/sql-createdatabase.html)。
模板、复制及删除仅使用夹具生成的唯一名称，不接收外部数据库名。

首轮接入七个普通测试类：容量策略权限、容量准入、容量诊断、容量策略业务、
Files 与 Identity 提交审计、PostgreSQL 事实交付恢复故障。
迁移、升级兼容、未迁移启动、独立迁移 CLI、真实进程重启旅程保留原入口与断言。
新公开 HTTP 旅程验证不同库可各自创建同名用户、一个库断线不影响另一个宿主就绪。
本轮再接入 29 个普通类，清单见票据。专用单上下文建库保留，以免新增模式遮蔽错误绑定；
迁移、未迁移启动与真实 OS 进程重启旅程保留原入口。
新增 Costing / Pricing 的 ISender 旅程验证同一对象与请求 ID 在不同库中独立受理、
查询不同输入，以及一个库取消任务不影响另一个库的待执行任务。

## 2026-10-06 阶段测量

同一共用 PostgreSQL、原有六模块夹具：新建空库约 0.2–0.4 秒，首次迁移约 8–10 秒；
同进程再次建空库并迁移仍约 8–9 秒，已迁移检查约 0.8–1 秒。
冻结自有模板并释放它的连接后，三次独立复制约 0.09–0.12 秒，五个平台 schema 均存在。
这些仅解释初始化阶段，不能代表整个 HTTP 旅程或 CI 的提速比例。

基线 PR #111 的完整共用环境运行：宿主 1093 项、工程墙钟 6306.7 秒；
首批七类 60 项累计用例约 735.3 秒。累计用例耗时与工程墙钟不能互换。
扩大回归 90 项全部通过；最终完整本机 23 工程 1932 项各执行一次，零失败、跳过、遗漏或重复。
首批七类原有 60 项在完整候选报告中累计 356.8 秒，较基线约减少 51.5%；
宿主工程增加隔离旅程后共 1094 项，墙钟 5924.8 秒（约 99 分钟），较基线约减少 6.1%。
两次完整观察不能排除环境波动，不能把七类收益冒充整体收益。
构建、格式、八个护栏、重命名模板构建与进度探针通过，私有配置未变。
完整 Linux CI 与合并结果以票据最新交付证据为准。
首次模板迁移仍有成本，宿主启动、HTTP 数据库往返、故障等待及真实 OS 进程旅程仍是剩余开销。

## 扩大回归中的故障与资格

扩大定向回归 265 项各一次通过；原 202 项身份精确保留，累计用例耗时由 1725.1 秒降至 878.6 秒，约少 49.1%。
这是筛选运行，不能代替完整宿主墙钟。随后完整 23 工程实际执行 1934 项，1933 通过、1 失败；该运行不是交付资格。
失败发生在来源库恢复后第一次容量读取返回 503，断线时的 503 和独立身份库的 200 均已通过。

所属临时库的 400 毫秒健康查询延迟可以稳定触发相同 HTTP 断言，策略读取记录了预算取消；
只使用生产默认三秒读取预算后同一场景通过。原始失败没有内部类型记录，不能据此证明那一次 503 的唯一原因。
普通来源断线和缺账本恢复旅程取消夹具的 250 毫秒缩短值；专门取消与短预算旅程仍显式保留 250 毫秒，
原 50 毫秒调用者取消、两秒等待上限、错误码、快照与残余查询断言保留。新增健康延迟 HTTP 回归先红后绿，五项故障回归通过。
产品超时、重试与连接池未变，临时观测已按字节还原。

此失败还让诊断等待暴露出来：原始日志曾在工程结束时才落盘，失败后约等 40 分钟才能定位。
外部 CLI 的运行中私有证据探针先红后绿，修正后四种成功/失败、中英文模式通过，普通输出继续脱敏。
该阶段尚无最终交付资格，新增延迟回归不参与原 202 项的耗时比较；最终本机结果见下节。

第二次完整检查在中央策略审计迁移旅程的首次宿主启动时记录 Identity 依赖不可用，未进入升级断言。
该测试及启动检查与 dev 基线一致，失败前扩大复用集合尚未执行；底层异常被启动检查隐藏，尚未确认根因。
失败现场与短循环的诊断证据留在本机私有目录，进度及票据只记录安全元数据；这轮同样不作为资格。
可选本地早停用于避免已失败的运行继续等待后续工作，不降低完整通过的覆盖要求。

## 扩大复用的最终本机结果

修正候选完成 Release 构建 → 共用 PostgreSQL 串行完整测试 → 格式检查，全部返回零。
23 工程发现和执行清单精确一致，1935 项各一次通过，零失败、跳过、遗漏或重复；
原 1932 项身份全部保留，新增两个业务 ISender 隔离旅程和一个健康延迟 HTTP 恢复回归。
八个护栏、独立 hive 重命名模板构建及其进度／早停探针通过，私有配置未变。

同一共用环境，29 类原有 202 项累计用例耗时从 1725.1 秒到 916.3 秒，减少约 46.9%。
新增延迟回归的 8.0 秒不计入这组对比。完整宿主现为 1097 项；
用两份 TRX 相同的 start / finish 边界比较，墙钟从 5923.9 秒到 5152.7 秒，
即 98.7 → 85.9 分钟，减少约 13.0%。累计用例耗时与工程墙钟仍不可互换。
本轮带已验证的外部被动观测，仅记录类型、SQLSTATE 与耗时；产品代码、超时、重试和业务连接池未变。
单次完整比较不能排除环境与执行顺序波动，也不能把定向回归的收益当成整体收益。

先前首次启动失败的审计迁移用例在本轮完整报告中通过（约 17.8 秒），
受控断库也已证明观测可捕获同一拒绝路径的 SQLSTATE；原始失败根因仍未确认，不声称已修复。
剩余主要热点的累计用例耗时为：恢复网关权限 24 项 411.4 秒、真实 Broker／进程恢复 7 项 363.3 秒、
文件持久化旅程 13 项 259.9 秒及 PostgreSQL 策略权限 12 项 166.5 秒。
这些仍保留全部场景和断言，本轮不扩大重组范围。
完整 Linux 四报告 Verify、统一门禁及 dev 合并结果以
[扩大宿主旅程空结构复用并校准 CI 实测权重](https://github.com/yongpengW/NexusStackNext/issues/114)
的最新交付证据为准。
