## 换机恢复

```powershell
git clone https://github.com/yongpengW/NexusStackNext.git
Set-Location NexusStackNext
git switch --track origin/codex/committed-audit-governance
dotnet restore NexusStackNext.slnx
dotnet build NexusStackNext.slnx
```

先安装仓库所需 .NET 10 SDK、PowerShell 7、Git、GitHub CLI，并恢复个人 GitHub 登录。配置按 `env/README.md` 和宿主启动文档恢复。`env/platform.dev`、`env/gateway.dev`、`env/test.dev` 含本机私密配置，故意不在 Git；通过可信私密渠道转移或重新配置，不得粘贴到 Issue、PR 或聊天。Redis 可由 platform / gateway 指向的配置中心 `Redis:ConnectionString` 获取，测试环境按现有测试约定注入；不要从截图猜测口令。

迁移命令先读对应持久化文档。用户允许开发期重新初始化迁移，但本检查点未执行共享库重置；不要仅因授权存在就自动删库。EF 工具版本须与项目 EF 10 一致。

测试前确认 PostgreSQL 上的其他使用者；当前开发库服务器同时承载配置中心。全量只允许串行：

```powershell
dotnet build NexusStackNext.slnx
pwsh -File scripts/run-tests.ps1
pwsh -File scripts/check-format.ps1
```

不要运行解决方案级并行 `dotnet test`。原机器临时日志、测试脚本和工具不在 Git，不作为新机器续做的依赖；以上提交内脚本才是入口。不要带走 bin / obj / 缓存来替代 restore。
