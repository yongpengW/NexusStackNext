# 主键只有一个权威：应用侧生成，数据库不做 IDENTITY

原项目 `Entity.cs:15` 在构造函数里赋雪花 ID，而 `SqlMigration/InitDatabase.sql` 里 22 张表
全部是 `GENERATED BY DEFAULT AS IDENTITY`，全仓没有一处 `ValueGeneratedNever`。
两个权威同时存在的结果是：序列永远停在第 1 个值，任何走"数据库生成"路径的插入都会拿到 `1`，
与种子数据里 `Id = 1` 的 admin 相撞（`UserSeedData.cs:30`）。

决定：主键一律由**应用侧**生成（雪花或 ULID），EF Core 侧显式 `ValueGeneratedNever()`，数据库列不带 IDENTITY。
ID 作为构造参数传入领域对象，不依赖任何静态单例（见 `AGENTS.md` 不变量 6）。

## Considered Options

- **数据库自增**：最简单，但分布式下会冲突，且违背"ID 在领域对象构造时就已确定"的要求。
- **数据库序列 + HiLo**：可行，但把 ID 的权威交回数据库，跨上下文分配会互相牵制。

## Consequences

- 每个上下文的主键生成器都是**显式依赖**，测试里可替换为确定性实现。
- 雪花依赖机器位，多实例部署必须保证 WorkerId 不重复——这一条要写进部署文档，并由配置中心统一下发，
  不能再像原项目那样各服务从本地 appsettings 各拿一个。
