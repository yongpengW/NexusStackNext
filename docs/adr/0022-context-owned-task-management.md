# 取消与续租保留业务意图，以原执行权和固定预算裁决

Costing 与 Pricing 需要延迟、取消和长计算续租，同时保留 NS/PoS 的稳定请求身份与可查询历史。
延续 [ADR-0019](0019-context-owned-business-tasks.md) 的所属数据库与短事务边界；本决定扩展其中
“首轮不续期”的范围，亦扩展 [ADR-0020](0020-transactional-cost-pricing-cooperation.md) 的有限计算协议。
票据为[业务任务管理：延迟、列表、取消与受约束续租](https://github.com/yongpengW/NexusStackNext/issues/48)。

## 决定

首次接受保存独立的 `CreatedAt` 与原始 `DelaySeconds`，延迟按同一次数据库时间采样计算。
请求重放先识别原意图，不因当前聚合版本、重试或重启重新计算期限。输入、原始延迟或来源不同
不能复用请求身份。旧任务原先没有延迟，升级为 0；其创建时间无法从可变的 `AvailableAt` 推导，
保持 null。迁移先添加可空列，再设置仅作用于未来插入的默认值，不能把升级时间伪造成历史。

取消是停止一次计算意图，不是回滚已接受的业务输入或撤回已发布事件。操作者必须提供观察到的
epoch；Pending / Retry / Running 可取消，Cancelled 在同代次重放原结论。取消不增加代次、
不制造未发生的尝试，运行中取消结束当前尝试；Succeeded / Superseded / Failed 或不同代次冲突。
Failed 保留原有条件重试入口；Cancelled 必须以新 RequestId 发起新意图，不能以旧请求复活。

每次领取将 `MaxLeaseUntil` 固定在所属数据库。续租要求 Running、相同 epoch、原租约仍有效，
候选期限为“数据库当前时间加 LeaseDuration”与持久总期限的较早值，而且必须严格延长。
续租不增加尝试与代次；重启时放宽配置不移动现有总期限。两个策略期限限定为整微秒，避免
应用认为增加了 100ns、数据库实际未改变的假成功。旧 Running 没有总期限，不能续租；其原租约
内仍可完成/失败，到期后新领取取得新的预算。

取消、续租、完成、失败、人工重试统一先锁任务行，再读取数据库当前时刻。
续租保存后复检**原期限**，失效就回滚；用新期限证明原执行权会让等待中的过期执行复活。
完成只在同一事务内修改本上下文的聚合、执行历史和可选 Outbox。锁顺序仍为任务 → 业务对象 →
尝试；不新增持有对象锁再等待既有任务行的反向路径。Redis 不参与最终写入权判断。

这是行锁保护下的条件裁决和提交后的可见顺序，不保证物理 COMMIT 的瞬间严格早于截止时间。
提交响应丢失属于未知提交，调用者应新建 scope 按稳定任务身份查询当前事实；不能把连接异常
自动解释为“肯定没提交”。也不承诺外部邮件、支付或任意 HTTP 副作用恰好一次。

## 运维查询与权限

列表只投影所属上下文的执行元数据，不加载输入或历史集合。每页最多 200 项、偏移最多 100000；
首次接受时间倒序，未知时间最后，再按 TaskId 升序。单页总数和条目在同一短 Repeatable Read
事务内读取，每个翻页请求仍有自己的快照。跨页期间有新增/状态变化时，稳定排序不等于完整快照。

列表和取消沿用当前根操作者授权；领取、完成、失败和续租只走所属 ISender，不暴露 HTTP。
跨宿主即时会话撤销与普通角色委派由 Identity 后续票据处理。批次检查点、私有异步导出与多机
高可用各有独立验收，不能从本协议的单机恢复测试推导出它们已经完成。

## 取舍

固定总预算会迫使超长工作失去租约，但避免持续心跳永久霸占一次领取；长批次应通过后续检查点
协议恢复。取消不回滚输入使状态更诚实，也要求调用方区分“当前输入尚未计算”和“任务正在运行”。
旧时间使用 null 增加了查询与展示分支，却避免让历史排序、排障和保留策略建立在虚构时间上。
技术依据与竞争矩阵见[协议研究](../research/2026-10-02-task-management-upgrade.md)。
