# 集成事件的契约名显式版本化，不用 CLR 类型名

原项目的路由键是事件的 **CLR 类型全名**（`EventSubscriber.cs:196/255/294-297`），
且事件注册表靠扫描**消费端**的 Handler 类型来发现。这意味着一次纯粹的重构——
把事件类挪到另一个程序集、或改一个命名空间——就会**静默切断消息链路**：
发布端与消费端各自算出一个不同的路由键，没有编译错误，也没有启动失败，消息只是不再到达。

决定：每个集成事件在 `*.Contracts` 里显式声明 `EventName`（形如 `identity.user-logged-in.v1`）与版本号。
路由键、队列名、幂等键一律基于它，**绝不**基于 CLR 类型名或命名空间。
交换机 / 队列 / 绑定的拓扑集中声明，不由消费端扫描推导。

## Considered Options

- **沿用 CLR 类型名**：零成本、无需登记，但把"程序集与命名空间布局"变成了消息契约的一部分——
  而这恰恰是本项目要动的东西（按上下文拆程序集），沿用等于给自己埋雷。

## Consequences

- 新增事件要显式登记一行。换来的是重构不会再断链，且契约可以在代码之外被审阅。
- 版本升级策略必须一次定清楚：v1 与 v2 如何并存、消费端如何按版本分流、旧版本何时下线。
