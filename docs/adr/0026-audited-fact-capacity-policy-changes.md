# 容量策略调整使用所属上下文的独立有限控制额度

业务事实额度满时，把扩容事实写入同一额度会阻止扩容；无条件豁免又会形成新的无界积压。
因此策略版本、请求凭据与最小调整事实在所属上下文内原子提交，使用独立且有限的控制额度。
这是一项来源存储治理协议，不写业务聚合，不借用中央操作 journal，不跨上下文读取账本。
六来源及四种 Memory 适配器的实施与验收由 [#101](https://github.com/yongpengW/NexusStackNext/issues/101) 跟踪；
真实迁移、消息交付和公开端口资格已由本票验证，测试入口见
[容量策略验收定位](../committed-auditing.md#容量策略验收定位)。
本决定的发布仍待独立双轴评审及当前提交的完整 Linux CI，不能将阶段验证当作已合并声明。

策略有单调版本，只有三个额度发生实际变化时推进。降低到当前保留总量以下不删除历史，
后续准入继续背压；空操作不推进版本、不发布 changed 事实。
同请求标识、可信操作者与同内容在凭据保留期间重放原结果，异内容或异操作者拒绝；
凭据被安全清理后重新按条件版本裁决；最早保留期限不是强制删除时刻，尚在保留的凭据仍用于重放或冲突判断。
请求标识不是事件身份，每次真实变化生成新的事件身份，避免清理后重用请求标识与中央 Inbox 冲突。

调整事实记录旧/新数值额度、版本、固定理由与可信执行关联，不收任意业务载荷或理由文本。
来源 Contracts 声明事件，中央 Auditing 保存类型明确的变化并沿用事务去重与内容指纹。
HTTP 尝试另由既有 journal 观察。各来源 Endpoints 通过 Auditing.Contracts 声明固定策略调整动作，
不序列化请求正文或任意理由作为日志说明；重放与拒绝仍有独立操作，已提交事实关联首次变更。
模块动作的归属与执行宿主的 Source 分开；平台宿主中的模块不伪装成独立执行来源。
中央的容量值对象与两个前后额度值对象存入自身 audit_entries 的明确列，普通事实保持为空。
数值变化参与新治理消息的指纹；没有治理值对象的旧消息继续使用原 legacy、Execution 或 RelatedSubject 形状，
新增字段不能导致已接受的旧消息重放冲突。治理事件只有 changed 标题而无数值时，领域拒绝登记。
中央新增独立增量迁移，升级保留已有事实和 Inbox 签名；已有数值证据时拒绝删除这些列的 Down。
控制池的条数、总字节和单条载荷均有上限；普通业务额度与控制额度不互相借用。
控制池满额时调整拒绝，不能假装已经记录审计。空操作的重放凭据也要占用有限控制额度。

Memory 的所属控制池可通过 `<Context>:AuditDelivery:MemoryPolicyControl` 在启动时缩小额度：
`MaxRecords` 为1–1000，`MaxPayloadBytes` 为1–16MiB，`MaxRecordPayloadBytes` 为1–16KiB且不超过总量。
默认值仍为1000条、16MiB、16KiB；这组配置不开放在线调整，也不参与业务容量策略PUT。
四个模块显式装配自己的不可变启动选项，即使关闭维护也拒绝无效配置。
PostgreSQL 始终读取所属持久账本，不使用这组 Memory 配置覆盖迁移后的额度。
启动时允许缩小额度既适用于有限开发环境，也使总字节边界可以通过公开存储端口独立验证：
默认1000条乘16KiB小于16MiB，若始终固定默认值，总字节判据会被条数或单条判据遮蔽。

凭据最早保留期限在接受时固定。到期且相关事实已确认交付、确认副本保留时间也满足后，
才能原子清理凭据和副本并释放控制额度；无事实的空操作凭据到期可清理。
待投递与死信不因到期删除。因此长期 MQ 故障仍可能用完控制额度，这是可见的背压，
不承诺在所有存储额度同时用完后仍无条件修复。

后台控制维护在 Platform 与 Identity 两个实际消费者的公开端口验证后收拢共同实现，六来源显式装配自己的键和配置。
共同实现只负责有限批次、预算、独立作用域和脱敏诊断；准入及原子删除仍由所属存储适配器实现。
维护诊断独立于业务就绪检查，成功后解除降级，关闭时保留明确开关状态；诊断计数不承诺跨进程持久化。
宿主停止取消正在等待的清理，不把正常停止记作故障，也不丢弃尚在执行的写任务。

PostgreSQL 的微秒存储精度不能缩短声明的最早保留期。凭据期限与 EF Outbox 首次确认时刻
向上取整到最早一个不早于真实时刻的可表示微秒；Memory 保留原精度。重复确认不改变首次时刻。
这是持久存储适配器的时间表示规则，不改消息发生时间、请求响应精度或冻结的 V1/V2。
中央的数据库故障继续走原消息重投，数值内容冲突走语义拒绝；两者不能混成一种死信结论。

PostgreSQL 使用所属独立连接和本地事务，Memory 使用所属共用写锁；两者都先完成可能失败的准备，
再一起发布策略与证据。锁预算和调用者取消不靠丢弃尚在运行的写任务实现。
PostgreSQL 策略连接显式禁用自动加入环境事务：调用者的 TransactionScope 回滚不撤销已经接受的独立策略裁决，
也不借用 EF 的未提交工作。维护清理仍要求独立作用域，发现环境事务直接拒绝。
既有业务计量 V1/V2 冻结，新协议通过正常增量迁移接入；有已接受控制历史时拒绝破坏性 Down，
不能用回退悄悄删除治理证据。控制池自身的在线策略修改不在本轮开放，避免递归治理。
