# 命令事务由所属上下文拥有，权限缓存在提交后失效

状态：accepted（2026-10-01）。票据：[Identity 命令事务归属与提交后权限缓存失效](https://github.com/yongpengW/NexusStackNext/issues/18)。

## 问题

平台宿主合并后，共享 Sender 从容器取得未区分上下文的 IUnitOfWork。
最后注册的工作单元会被所有命令使用；另一个 DbContext 的 SaveChanges 无法保存 Identity 的授权变化。
仓储又自行保存，导致返回业务失败的命令仍可能提交此前的部分写入。

权限处理器在事务提交前使缓存失效。此时并发查询可把数据库中的旧权限写入新版本缓存，
命令成功后仍读到旧权限。另一个竞态是提交后的请求加入了提交前尚未完成的单飞读取。

## 决定

- Sender 只校验和分发，不从全局容器选择工作单元。
- Identity 显式装饰自己的命令处理器，使用 IIdentityUnitOfWork。查询不进入命令事务。
  这个端口变化的是存储的事务语义，已有 EF 与内存两个适配器；Identity 特有的提交策略留在本上下文。
- EF 仓储登记改动，不自行 SaveChanges。命令边界统一保存并决定提交；普通失败和异常回滚，清除失败的跟踪状态。
- 密码错误计数与刷新令牌重放撤销是需要保存的安全状态。
  处理器显式登记对应拒绝，提交判据只接受成功或该拒绝，不把所有业务失败都视为可提交。
- 缓存失效和本进程会话版本更新在提交成功之后执行，不放进可能重试的数据库操作内。
  每次执行或重试重新登记这些意图，失败后清理，禁止嵌套发送 Identity 命令。
- 权限单飞的键包含用户和版本；较早的回源不能替换较新的缓存条目。
- 签发令牌先完成校验与准备，再消费旧令牌。签发失败时，内存适配器也保留原令牌可用性。

## Considered Options

- **所有上下文共用一个工作单元**：会让模块依赖注册顺序，违反数据归属。
- **业务失败一律提交**：会持久化半成品。
- **业务失败一律回滚**：会丢失密码错误次数及重放检测后的撤销。
- **通用事务行为链及任意提交回调**：目前只有 Identity 需要这些策略，暂不建立框架。

## Consequences

仓储的 AddAsync 现在表示登记写入。直接调用 EF 仓储的维护程序或适配器测试必须显式提交；
正常入口经 ISender 调用已装饰的处理器。新增 Identity 命令必须沿用同一注册入口。

默认宿主仍使用内存存储；该适配器直接持有对象，不提供数据库级隔离、异常回滚或崩溃恢复。
本次真实事务保证由 PostgreSQL 适配器提供，不代表默认宿主已经具备生产持久化。
权限缓存和会话版本仍在本进程内；多实例失效、提交后进程退出的恢复需要持久化版本或可靠事件，留待后续工作。

本决定明确事务归属和提交时机，不证明聚合边界已经全部正确。
现有登录、令牌轮换及批量撤销仍涉及多个聚合，未在本轮重新建模；“一个聚合一个事务”仍需单独审查这些流程。
数据库在提交确认阶段断线也可能导致结果不确定，本轮不提供命令幂等键或恰好一次承诺。

## 验证

用户确认的测试面是 ISender 命令/查询与 Identity HTTP。
真实 PostgreSQL 测试验证外来工作单元不影响 Identity、失败签发可重试、提交失败后同作用域可重试、
提交期间权限读取及旧回源跨越提交这两种竞态。宿主 HTTP 测试验证内存适配器签发失败可重试。
已有登录锁定、重放撤销、HTTP 授权及架构测试继续守住原有行为。
