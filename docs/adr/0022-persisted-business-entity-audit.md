# 业务行审计与开发阶段迁移重建

## Context

NS / PoS 的业务实体保存创建与修改时间、操作者。NSN 已有 `IAuditedEntity` 和审计拦截器，
但生产实体没有实现接口，迁移也没有列。探针测试只验证机制和装配，未验证真实业务实体。
用户于 2026-10-02 确认 NSN 尚无历史数据，允许将开发期迁移链重建为初始迁移。

## Decision

九个业务聚合使用 `AuditedAggregateRoot<TId>`：User、Role、ApiResource、MenuTree、
GlobalSetting、StoredFile、ScheduledTask、CostSheet、PriceQuote。
共同的四个字段是持久化元数据，领域方法不取环境时间、用户或推进额外版本。
创建时间必填 UTC；创建者和修改者是当前认证操作者的标识，系统或匿名写入为空。
首次创建不填修改字段，创建信息不随后续修改漂移。

真正的变更才更新修改字段。分离实体即使被适配器整体标为 Modified，
当原始与当前 Version 相同时仍保留原审计信息与乐观并发检查。
审计与业务行写入在同一事务里，拒绝、冲突、回滚不能留下独立的审计变化。
这是最近创建/修改信息，不是完整操作历史；已提交事实仍由 Auditing 单独记录。

当前操作者通过宿主显式组装的 `ClaimsCurrentUser` 读取已经认证的声明。
后台作用域没有 HTTP 身份，不能借用原委托人的身份。Scheduling 的 `DelegatedBy` 单独
保存原委托人，已有事件与 HTTP `createdBy` 保持原委托语义；嵌套 `audit.createdBy`
表示持久化创建者。Costing 的接收凭据保留原委托信息。

审计契约适用于业务聚合根。菜单节点、角色菜单和用户角色关联的变更由所属根的版本与
修改审计负责；AuditEntry、RefreshToken、Inbox/Outbox、任务/尝试/发生项、接收凭据、
缓存失效与存储回收记录保留各自事实或生命周期，不添加无意义的修改字段。
新增聚合必须选择行审计或明确登记生命周期例外，由结构测试检查，真实业务测试验证落库。

公开安全读取使用嵌套 `audit` 元数据。尚未持久化的领域对象及 Memory 演示模式返回空，
不把默认时间伪装成真实创建时间。PostgreSQL 是行审计的验收适配器。

开发期旧迁移链整体退役，七个上下文分别保留一套完整初始迁移及模型快照，
继续各自拥有 schema 与迁移历史表。旧的历史升级测试改为初始化与重复迁移验证。
已有约束、计算列、索引、精度与外键保留。现存开发库需要重建对应 NSN 结构；
不能只清空迁移历史表后在旧表上执行初始迁移，也不能删除共享配置中心或其他项目的库。
参考：[EF Core 迁移管理](https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/managing)。

## Considered Options

- 只增加字段：不会自动产生可信时间或操作者，不能通过真实写入验收。
- 给全部实体基类加字段：把行审计强加到不可变事件、令牌等对象，混淆生命周期。
- 每个应用用例手填：容易漏掉后台、失败登录和后续新增入口，也容易信任客户端输入。
- 保留旧迁移并补列：用户明确无历史数据，当前无需承担历史回填与升级兼容。

## Consequences

已有聚合直接复用公共审计基类，普通领域代码仍无基础设施依赖；接口赋值仅用于基础设施。
Costing / Pricing 显式只挂审计拦截器，保留其现有业务事务与 Outbox 协议。
Pricing 缓存投影随公开响应增加审计信息同步升级，旧格式不继续服务缺少元数据的响应。
Memory 模式用于演示而不提供持久化审计保证。进入生产后不得再重写已应用迁移；
届时模型变化采用增量迁移。
