# 由接纳端拥有事务 Inbox，两个上下文共用任务执行协议

Costing → Pricing 只通过 Costing.Contracts 中的 CostCalculatedV1 通信。两个宿主和数据库独立，
没有跨库读取或远程事务。Costing 结果与 Outbox 同事务；Pricing 的 Inbox、成本投影及重算登记同事务，
事务提交后运输层才 ACK。提前在运输层提交 Inbox 会在进程崩溃时永久跳过未完成业务，因此移除那条路径。

Pricing 保留自己的费率；首次成本事件可创建默认费率为零的演示对象，已有对象保留费率并转为由 Costing 维护成本。
此后手工成本覆盖被拒绝，费率可单独修改。来源版本与本地输入版本分别记录，重复、旧版本为空操作，
同一来源版本的不同成本被拒绝。观察状态变化才递增聚合 Version。
Pricing 在自己的 Inbox 映射中同事务保存规范化载荷指纹；同一消息标识的不同内容被拒绝，
包括第一次因版本旧而被忽略的消息。该列只属于 Pricing，不扩展其他上下文的公共 Inbox 契约。

Pricing 与 Costing 都有持久化快照、租约、有限尝试和历史后，提取 PostgresTaskExecution 与执行元数据。
共享模块只操作调用者的 DbContext；公式、业务快照、查询形状、聚合修改和事件仍在上下文内。
任务映射与完成结果枚举也由公共模块维护，两个调用方不再复制持久化协议或拼写终态。
没有中央任务数据库，也没有跨上下文事务。有限计算不增加长任务心跳或外部副作用重放承诺。

有效消息因数据库暂时故障无法接纳时，保留原消息并退避重投，不经过 TTL/DLX。
确定性非法事件经 mandatory + publisher confirms 搬到消费端死信队列，确认后才 ACK 原消息。
既有显式重试档位仍可供其他订阅使用，但经典队列内部 TTL/DLX 不具备同等可靠转发保证。
多机 broker/数据库高可用按用户要求放在全部能力之后单独开票，不由本轮单机恢复验证代替。
