# 跨上下文只通过契约程序集与集成事件通信

决定：上下文之间只允许两种通信——`*.Contracts` 程序集（集成事件 / DTO），或事件总线上的集成事件。
禁止同步调用其他上下文的业务接口，禁止引用其他上下文的 `Domain` / `Infrastructure`。
数据库写入与事件发布的一致性由 **Outbox** 保证，消费端按幂等键去重（Inbox）。

## Considered Options

- **跨上下文同步 HTTP**：时序直观，但一个上下文不可用会级联拖垮上游，跨上下文的"事务"更无从谈起。
- **共享数据库当集成点**：原项目就是这个形态——所有上下文通过同一个 DbContext 相互锁死。

## Consequences

- 所有跨上下文流程都是最终一致的，接口与 UI 必须能表达"处理中"这一状态。
- 每个发布事件的上下文都需要 Outbox 表与投递器。按不变量 7，它要在第二个消费者出现后才上移 `BuildingBlocks`——也就是说第一个上下文先自己实现一份。
